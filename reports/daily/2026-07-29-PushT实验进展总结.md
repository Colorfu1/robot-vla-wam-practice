# 2026-07-29 PushT 实验进展总结

## 重要进展

- 截至当日，BCChunk 与 Diffusion 均完成 200,000 updates 的受控训练，并通过
  20 个 development seed 的闭环选模确定 BCChunk-150k 与 Diffusion-175k。
- E0 `Offline / Formal` 完成 206 条 demonstration 的全量审计；数据具有丰富的
  全局轨迹形态，但不能据此声称相同 observation 下存在多个有效 action mode。
- E1 `Offline / Formal` 将随机性来源拆开：只改变 initial noise 时输出几乎不变，
  改变完整 DDPM sampling stream 后 action chunk 出现约 2–3 px 的差异；进一步的
  action-mode 分析仍是 0/10 candidate 通过。
- E2 `Closed-loop / Formal` 完成 220 条主实验 rollout：BCChunk 为 5/20，
  Diffusion 单次部署估计为 11/20，全部 Diffusion samples 为 105/200，
  any@10 oracle coverage 为 18/20。
- E3 `Closed-loop / Formal` 完成 6 个采样条件、300 条 rollout。DDIM-5 用
  47.73 ms 的 p95 chunk latency 达到 58% success，相对 DDPM-100 的 60% 和
  600.15 ms，在 success 只下降 2 个百分点时加速 12.57 倍。
- E4 `Closed-loop / OOD diagnostic` 表明未适配的原始 Diffusion Policy 无法直接
  完成新构造的旋转场景；接触点偏移会显著改变最大重合度，但没有诱导出相反接近方向。

## 实验链路与统一协议

本阶段围绕同一组 PushT 数据和冻结模型依次回答四类问题：

1. 数据中有什么轨迹结构（E0）；
2. 固定 observation 下采样是否改变 action chunk（E1）；
3. 随机采样差异能否在闭环中形成不同结果（E2）；
4. 减少采样步数能否保留 success 并降低延迟（E3）。

E4 是额外的 OOD 场景诊断，不使用 E4 专用训练数据，不能与 E0–E3 的原任务性能
结论混为一谈。

| 字段 | 统一设置或状态 |
|---|---|
| Task suite | PushT；E4 为自定义 PushT OOD 场景 |
| Dataset size | 206 episodes；165 train / 20 development / 21 held-out audit |
| Observation keys | 96×96 RGB `observation.image` + 2D `observation.state` |
| Observation history | 2 帧 |
| Action space | 2D absolute target position |
| Action horizon | 内部 horizon 16；每次执行 `[1:9]` 共 8 个 actions |
| Control frequency | 10 Hz |
| Train loss | BCChunk 最后日志 0.000（仅三位小数）；Diffusion epsilon loss 0.004 |
| Open-loop action error | 选中 BCChunk / Diffusion 的 denormalized MSE 为 582.31 / 1169.87 |
| Closed-loop success | development 11/20 / 16/20；E2b 5/20 / 11/20（单 sample） |
| Latency | E3 DDIM-5 / DDPM-100 p95 chunk latency 为 47.73 / 600.15 ms |
| 主要 failure cases | development 两者都失败 3 个 seed；E2b 有 2 个环境在 10 次 Diffusion sampling 中全部失败；E4 全部失败 |

BCChunk 和 Diffusion 使用相同数据、预处理、视觉编码器、temporal U-Net 容量、
optimizer、scheduler 和成对 step-zero 初始化。核心受控差异是：

- BCChunk 直接回归 clean action chunk；
- Diffusion 预测 epsilon，并通过多步反向去噪生成 action chunk。

两种 train loss 的语义不同，不能直接比较绝对数值。

## 正式训练与闭环选模

模式：训练为 `Formal`；checkpoint selection 为 `Closed-loop / Formal`。

两个模型均保存 25k 到 200k 的 8 个 checkpoint。20 个 development seed 的选模
结果为：

| 模型 | 选中 step | Development success | Mean max reward | Offline denormalized MSE |
|---|---:|---:|---:|---:|
| BCChunk | 150k | 11/20，55% | 0.8652 | 582.31 |
| Diffusion | 175k | 16/20，80% | 0.8790 | 1169.87 |

最低 offline MSE、最后 checkpoint 和最高 closed-loop success 并不重合。逐 seed
对比中，仅 BCChunk 成功 1 个、仅 Diffusion 成功 6 个、两者都成功 10 个、两者都
失败 3 个。Diffusion 在 development 上高 25 个百分点，但 exact two-sided
McNemar 检验为 `p=0.125`，而且这些 seed 已用于选模，因此只能说明方向有利，不能
作为独立 held-out 泛化结论。

## E1：固定 Observation 的双协议采样

模式：`Offline / Formal`。10 个 held-out observation candidate，每个协议生成
20 个 Diffusion action chunk，不执行环境动作。

| 指标 | E1a：initial noise only | E1b：full sampling seed |
|---|---:|---:|
| Denormalized trajectory pairwise RMS | 0.00659 px | 1.94563 px |
| Denormalized endpoint pairwise distance | 0.00750 px | 2.80300 px |
| 相同条件 repeat max error | 0 | 0 |
| 通过 action-mode 判据的 candidate | 0/10 | 0/10 |

E1a 只改变 initial noise、固定 reverse seed；E1b 同时改变 initial noise 和完整
reverse sampling stream。E1b/E1a 的 trajectory RMS 约为 295 倍，endpoint
distance 约为 374 倍，说明主要差异来自完整反向采样过程，而不是 initial noise
本身。

但 E1 的 GMM/BIC 与完整 chunk 距离交叉分析没有找到候选 action mode，BC
averaging-consistent signature 也是 0/10。因此 E1 支持“完整 DDPM sampling 会
改变 action pattern”，不支持“固定 observation 的动作分布已被证明多峰”。

机器结果位置：
`outputs/pusht_diffusion/pilot/e1_fixed_observation/metrics.json` 和
`outputs/pusht_diffusion/pilot/e1_fixed_observation/action_mode_analysis/metrics.json`。

## E2：双协议闭环 Sampling

模式：`Closed-loop / Formal`。

### E2a：Initial-noise sensitivity

E2a 使用 2 个 environment seed × 5 个 policy seed，只改变 initial-noise stream：

- success：5/10；
- first-replan chunk diversity：`4.17e-5`；
- 至少两个 distinct successful mode 的环境：0/2。

这说明很小的初始动作差异可能在部分闭环环境中被放大，但 E2a 没有形成多个成功
mode 的证据。

### E2b：Full DDPM sampling

E2b 使用 20 个 environment seed × 10 个 Diffusion policy seed，并在同一批环境
各执行一条 deterministic BCChunk：

| 指标 | 结果 |
|---|---:|
| BCChunk success | 5/20，25% |
| Diffusion `policy_seed=0` | 11/20，55% |
| 全部 Diffusion samples | 105/200，52.5% |
| any@10 oracle coverage | 18/20，90% |
| 至少 2 条成功 rollout 的环境 | 16/20 |
| 至少 2 个成功轨迹簇的环境 | 16/20 |
| Mean successful mode count | 3.9 |
| Max successful mode count | 8 |
| 成功/失败 trajectory diversity | 0.11576 / 0.18217 |

完整 sampling stream 会实质性改变闭环结果，16/20 个环境同时具有至少两个按
complete-linkage 距离阈值定义的成功轨迹簇。这支持“多个成功闭环行为 mode”，但
这些 mode 是轨迹空间的操作性分组，不等同于左/右等人工语义策略，也不能反向推导
固定 observation 的 \(p(a\mid o)\) 已被证明多峰。

any@10 是尝试 10 次后至少一次成功的 oracle coverage，不是单次部署成功率。单次
部署更接近固定 `policy_seed=0` 的 55%。失败轨迹比成功轨迹更多样，说明更高
diversity 并不自动带来更高 success。

机器结果位置：
`outputs/pusht_diffusion/pilot/e2a_initial_noise_sensitivity/metrics.json`、
`outputs/pusht_diffusion/pilot/e2b_full_ddpm_sampling/metrics.json` 和
`outputs/pusht_diffusion/pilot/e2b_full_ddpm_sampling/mode_analysis.json`。

> 说明：当日较早生成的 E2 专题草稿记录了旧一轮结果；本总结以晚间最终机器指标
> 为准。

## E3：采样步数、成功率与延迟

模式：`Closed-loop / Formal`。6 个条件各使用 50 个 environment seed，共 300 条
rollout；延迟为 batch size 1、同步计时的 raw observation 到 8-action chunk
end-to-end p95。

| 条件 | Success | p95 latency | 相对 DDPM-100 加速 |
|---|---:|---:|---:|
| DDIM-5 | 58% | 47.73 ms | 12.57× |
| DDIM-10 | 56% | 71.86 ms | 8.35× |
| DDIM-20 | 58% | 121.41 ms | 4.94× |
| DDIM-50 | 54% | 307.67 ms | 1.95× |
| DDIM-100 | 58% | 601.05 ms | 1.00× |
| DDPM-100 | 60% | 600.15 ms | reference |

预注册目标是至少加速 2 倍，同时 success drop 不超过 5 个百分点。DDIM-5、10、20
均满足，DDIM-5 的 p95 最低，因此是当前 checkpoint 的推荐部署配置。这个结论只
适用于当前模型、评测协议和计时环境，不应直接外推到其他硬件或任务。

机器结果位置：
`outputs/pusht_diffusion/pilot/e3_sampling_steps/metrics.json` 和
`outputs/pusht_diffusion/pilot/e3_sampling_steps/condition_metrics.json`。

模式：`Closed-loop / OOD diagnostic`。E4 没有构造训练数据，只把原 PushT
Diffusion-175k 放入新场景。

### 同中心纯旋转

固定同一初始状态运行 5 个 sampling seed：

- success：0/5；
- mean max reward：0.5284；
- best max reward：0.5858；
- 5 条轨迹全部达到 300-step time limit。

### 左下角到中心的 180° 场景与接触点偏移

left-up、center、right-down 三个接触点条件各运行 5 条：

| 接触点 | Success | Mean max reward | Best max reward |
|---|---:|---:|---:|
| left-up | 0/5 | 0.1595 | 0.1648 |
| center | 0/5 | 0.2266 | 0.4110 |
| right-down | 0/5 | 0.5664 | 0.8441 |

向右下移动接触点显著提高了最大重合度，但 15 条轨迹仍全部失败，也没有观察到从相反

## 当前可以支持的结论

1. **Closed-loop checkpoint selection 是必要的。** 最低 offline MSE 和最高
   closed-loop success 不一致。
2. **Diffusion-175k 在 development set 上方向优于 BCChunk-150k。** 80% 对 55%，
   但不具备独立 held-out 证据。
3. **完整 DDPM sampling stream 是当前随机行为差异的主要来源。** Initial noise
   单独变化几乎不改变首个 action chunk。
4. **完整采样能够产生多个成功闭环轨迹簇。** E2b 的 16/20 个环境满足预注册的
   多成功 mode 判据。
5. **当前没有固定 observation action distribution 多峰的直接证据。** E1 的
   action-mode 分析为 0/10。
6. **DDIM-5 是当前最优部署点。** 相对 DDPM-100 success 下降 2 个百分点，p95
   chunk latency 加速 12.57 倍。

## 限制与风险

- Development 结果复用了 checkpoint-selection seed，不能当 final 泛化结果。
- E2 的成功 mode 是距离阈值定义的轨迹簇，不是人工语义标签；它不证明
  Diffusion 已克服 MSE mode averaging。
- `policy_seed=0` 与全部 sample success 回答不同问题；any@10 更是 oracle coverage，
  三者不能互换。
- E3 的延迟依赖运行环境；这里只比较同一协议内的相对 Pareto。
- E4 是未适配策略的 OOD diagnostic，不是 E4 任务可学习性的评测。

## 下一步

1. 对 E2 的代表性成功/失败轨迹做人工语义复核，确认距离簇是否对应可解释策略。
2. 构造带显式 mode 或 prototype 条件的正对照，区分“随机闭环分叉”和“可控策略模式”。
3. 若继续 E4，先采集同初始状态的配对 demonstration，再训练和评估，不再用原模型
   OOD rollout 代替可学习性实验。
4. 补充独立 final environment seeds，避免 selection set 上的方向性优势被误写为
   泛化优势。
