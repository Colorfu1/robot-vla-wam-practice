# 2026-08-04 Z0 基线与 C1 目标适配正式评测结论

## 重要进展

- Z0（selected B0 原样零样本）与 C1（selected 030000）在**同一份冻结的 210 条目标协议**上
  各跑一次，两次 `status=complete`，协议字段除策略路径外逐项相同，因此两组成绩可比。
- **目标任务适配的提升是压倒性的**：canonical 成功率从 Z0 的 0/90（0.0%）升到 C1 的
  87/90（96.7%），三个任务各 29/30。Z0 那 90 条全部 `time_limit` 超时，一次都没成功。
- **语言泛化是明显短板**：C1 换成训练时未见的改写句后掉到 30/90（33.3%），
  `para_gap` 点估计 +0.6333、bootstrap 95% CI `[0.5222, 0.7333]`，区间不含 0。
- **Prompt Swap 暴露的是"单目标不可达"而非"均匀听不懂"**：C1 整体依从 18/30（60.0%），
  但 cabinet 指令 10/10 达成、plate 8/10 达成、**stove 0/10 且无一跑向其他目标**。
- Z0 的 Prompt Swap 为 0/30，30 条全部 `no_goal_reached`，混淆矩阵全落在 failed 列。零样本下
  不存在可言的指令依从，这不是协议失效。
- 同一份 B0 权重被以两个路径各跑一次（`checkpoints/025000` 与 `checkpoints/selected`，
  sha256 同为 `811bd1a7ba06c32b…`），四个指标块**逐值完全相同**，附带验证了评测的确定性。

## 核心结论

### 1. 113 条示范足以让 B0 学会三个新任务，B0 自己完全不会做

Z0 与 C1 用的是同一个 B0 权重家族的两端：Z0 是 selected B0 原样，C1 是从同一个 B0 出发、
用 113 条目标示范训练 30,000 步的结果。唯一变量就是这段训练。

| 协议 | Z0（B0 零样本） | C1（目标适配） |
|---|---:|---:|
| canonical | 0/90 = **0.0%** | 87/90 = **96.7%** |
| held-out paraphrase | 2/90 = 2.2% | 30/90 = 33.3% |
| prompt compliance | 0/30 = 0.0% | 18/30 = 60.0% |

逐任务 canonical：C1 为 29/30、29/30、29/30，三个任务齐平；Z0 三个任务全为 0/30。

B0 在自己的 37 个背景任务上有 0.8714 的 test 成绩，但对这三个从未训练过的任务是完全不会做，
90 条全部超时。这说明 SmolVLA 在本设置下**没有表现出跨任务零样本迁移**，任务适配是必需的。

### 2. C1 学到的是指令与动作的固定绑定，不是语言理解

canonical 96.7% 对 held-out paraphrase 33.3%，差距由 `para_gap` 量化：点估计 +0.6333，
90 个配对 case 上 bootstrap 95% CI `[0.5222, 0.7333]`，区间完全不含 0。也就是说换一种说法
之后约三分之二的任务做不成。

逐任务看掉幅不均匀：task 1 从 29/30 掉到 8/30，task 8 从 29/30 掉到 7/30，
task 4 相对最好（29/30 → 15/30）。

C1 训练只用 canonical 指令，这个结果是它的直接后果，也是 C3（25/75 混合改写句训练）要针对的
问题。本次为 C3 提供了可比的基线数。

### 3. Prompt Swap 的 60% 依从率不能读成"六成听懂"

C1 的混淆矩阵（行=给的指令，列=实际达成的目标）：

| 指令 | cabinet | plate | stove | failed |
|---|---:|---:|---:|---:|
| cabinet | **10** | 0 | 0 | 0 |
| plate | 0 | **8** | 0 | 2 |
| stove | 0 | 0 | **0** | **10** |

cabinet 与 plate 两个目标是真在听指令（10/10、8/10），而 stove 指令 10/10 全部失败，且**没有
一条跑去达成别的目标**——是做不到，不是听错。所以 60% 是"两个目标能听、一个目标不可达"的
合成值，而非在三个目标上均匀达成六成。

Z0 侧 30/30 全部 `no_goal_reached`，混淆矩阵三行都只有 failed 列非零，符合"零样本下指令
不起作用"的预期。

### 4. 动作平滑度与延迟同向改善

| 指标 | Z0 | C1 |
|---|---:|---:|
| 模型查询延迟 p50 | 310.1 ms | 285.3 ms |
| 模型查询延迟 p95 | 471.3 ms | 443.2 ms |
| action TV | 0.0483 | 0.0268 |
| action jerk | 0.0706 | 0.0285 |
| 平均 gripper 切换次数 | 18.62 | 3.76 |

Z0 的 gripper 切换是 C1 的近 5 倍、jerk 是 2.5 倍，与"反复尝试直到超时"的失败形态一致。
延迟差异较小，主要来自成功 episode 更短（C1 成功平均 114.3 步）。

## Development / Validation checkpoint selection

结果类别：`Formal / Closed-loop / Validation`。6 个 checkpoint × 3 任务 × 20 个 validation
初始状态 = 360 条闭环 rollout，外加每个 checkpoint 在 30 条离线 validation demonstration
（2,969 帧）上的开环动作误差。

| Rank | Step | Macro SR | Offline norm MSE | Successes | 生效判据 |
|---:|---:|---:|---:|---:|---|
| 1 | **030000** | **0.9833** | 0.309668 | 59/60 | winner |
| 2 | 025000 | 0.9833 | 0.311054 | 59/60 | level 2 |
| 3 | 015000 | 0.9833 | 0.324043 | 59/60 | level 2 |
| 4 | 020000 | 0.9667 | 0.310969 | 58/60 | level 1 |
| 5 | 010000 | 0.9500 | 0.335584 | 57/60 | level 1 |
| 6 | 005000 | 0.8833 | 0.389176 | 53/60 | level 1 |

三个 checkpoint 在主判据上并列 0.9833，最终由第二判据（macro 归一化开环动作误差）分出
030000。这印证了引入开环判据的必要性：macro 成功率粒度只有 1/60，并列是常态。

**validation 的 0.9833 不是无偏成绩**（同一批 60 个 case 被六个 checkpoint 各看过一遍），
无偏成绩是 test 上的 96.7%。

## 协议一致性核对

三份 `run_manifest.json` 的 `contract` 中仅以下字段不同：`model_label`、`policy_path`、
`policy_config_sha256`、`jobs`。`jobs` 的差异逐 job 核对后仅在 `output_dir` 与 `log_path`，
init states、episode seeds、指令文本三份完全一致。以下字段三份相同：

- `split_sha256` `f323688693cba919…`、`paraphrases_sha256` `4f4891da2570f3bf…`、
  `protocol_config_sha256` `366069c1f40de11e…`
- `env_seed=1000`、`policy_seed=2000`、`n_action_steps=10`、`num_gpus=8`、`max_steps=None`
- `protocols=["canonical","held_out_paraphrase","prompt_swap"]`、`total_rollouts=210`

## 必填实验字段（C1）

- Task suite：LIBERO-Goal 三个目标任务（本地编号 1 / 4 / 8）
- Dataset size：训练 113 条 demonstration / 11,022 帧；离线 validation 30 条 / 2,969 帧
- Observation keys：两路 256×256 RGB + 8 维 `observation.state`
- Action space：7 维相对末端动作
- Action horizon：`chunk_size=50`，执行 `n_action_steps=10`
- Control frequency：10 Hz
- Policy：从 selected B0（step 25000，`selection_set=background_validation`）出发；
  `freeze_vision_encoder=True`、`train_expert_only=True`、PEFT 关闭；
  `data_parallel_layout=8x1`（全局 batch 8）、BF16、30,000 步、每 5,000 步保存；
  AdamW LR 1e-4 / betas (0.9,0.95) / eps 1e-8 / wd 1e-10 / clip 10；
  warmup 1,000 + cosine 30,000 → 2.5e-6；train seed 1000
- Train loss：30,000 updates，首步 0.1599，末 1,000 步均值 0.01739；loss/grad norm/LR 全程
  有限，grad norm 峰值 9.42，LR 峰值 9.99e-5、终值 2.5e-6；8 个 rank 状态均为 `complete`
- Open-loop action error：选中 checkpoint 归一化 0.309668 / 去归一化 0.040252
- Closed-loop success rate：validation macro 0.9833（59/60）；test canonical macro 0.9667
  （87/90）、held-out paraphrase 0.3333（30/90）、prompt compliance 0.6000（18/30）
- Latency：模型查询 p50 285.3 ms、p95 443.2 ms（21 个 job 均值）
- Failure cases：canonical 3 条 `time_limit`；held-out paraphrase 60 条 `time_limit`；
  prompt swap 12 条 `no_goal_reached`（其中 stove 指令 10 条全失败）

## 结论边界

本次实验支持：

- selected B0 对三个目标任务是零样本不可用（canonical 0/90）；
- 113 条目标示范的 Non-PEFT 适配把 canonical 成功率提到 96.7%，三任务均衡；
- C1 对训练时未见的改写句泛化差，掉幅经 bootstrap 区间确认；
- C1 的指令依从在三个目标上不均匀，stove 目标不可达。

本次实验不支持：

- "C1 泛化到新摆放"——30 个 test 初始状态与训练摆放同属约 3 cm 范围的同一分布，测的是同任务、
  未被使用过的摆放；
- "C1 优于 LoRA 方案"——C2/C3 尚未训练与评测；
- 任何关于 Z0 与 C1 差异显著性的定量陈述——除 `para_gap` 外未做配对检验，配对单位应为
  task/init-state/protocol 三元组；
- 把 prompt compliance 60% 解释为均匀的指令理解能力。
