## 实现与范围

- [启动脚本](../scripts/experiments/rl/run_lightwam_train_scene_eval.sh)
- [配对评测实现](../src/robot_practice/experiments/rl/lightwam_train_scene_eval.py)
- [测试](../tests/experiments/rl/test_lightwam_train_scene_eval.py)

默认选择 NPZ 轨迹 `0,10,20,30,40,50,60,70`，与已有训练轨迹开环诊断一致。
HDF5 为 `datasets/raw/robomimic/square/mh/demo_v141.hdf5`；NPZ 与 normalization
来自 `datasets/raw/dppo/robomimic/square-img/`。本地运行逐条唯一匹配成功。

用 HDF5 的环境元数据、逐轨迹 XML 和初始仿真状态恢复场景，摄像头设为 agentview 96×96。
单个 DPPO Python 子进程运行仿真；LightWAM 在独立 Python 环境推理，进程间仅传 RGB、自身状态、动作和指标。
强制 OSMesa，并验证实际 renderer 为软件渲染器。无自动重置，无逐步恢复示范状态，无示范未来帧输入模型。
独立的观测审计会恢复初始、中间、闭爪前的示范状态；审计后重新恢复初始场景才开始连续回放。

初始状态门槛：完整仿真状态最大绝对误差 ≤1e-8；归一化 proprio ≤1e-3；图像 MAE ≤10/255。
图像门槛只是可配置的明显不一致筛查，不证明视觉输入对策略等价。保存训练图与重渲染图并排 PNG，
同时报告上下翻转后的误差供检查，不自动翻转图像以追求通过。
只评测初始观测检查通过且完整示范回放成功的场景；覆盖数与成功率同时报告，排除项不计为策略失败。

## 已测结果与限制

本地8条初始图像 MAE 为1.081–1.164/255，自身状态误差在浮点精度范围。
完整示范连续回放7/8任务成功；轨迹60不成功，尚未定位其回放偏离原因。
记录了连续回放的仿真状态误差，成功回放不等于每一步仿真状态都精确相同。

轨迹50示范长503步，首次成功499步。默认模型预算仍为400步，不能要求所有示范可达状态都能在此预算完成。
结果分别提供完整示范与 `within_policy_budget`，必要时另起 `--max-steps=600` 实验，不覆盖400步结果。
`task_success_any_step` 使用环境原生任务成功信号；`official_chunk_success` 要求某个完整4步动作块奖励和≥4。
短示范末尾的成功可能不满足完整动作块规则，两者分开记录，不混报。

本地验证：11项单元/驱动回归测试、Ruff、shell语法检查通过；真实示范回放已执行。
远端恢复与模型闭环尚待执行，本地结果不可写成远端结果或 LightWAM 成功率。

## 运行

先同步新增 Python 模块、shell 入口及原始 HDF5 到离线运行仓库，无需修改 vendor 或重建 Docker。
在运行仓库根目录执行：

```bash
# 只验证恢复和示范回放，不加载训练权重。
GPU=0 bash scripts/experiments/rl/run_lightwam_train_scene_eval.sh --replay-only

# 默认评测 step_102500，先回放示范，再测通过门槛的场景。
GPU=0 bash scripts/experiments/rl/run_lightwam_train_scene_eval.sh

# 可通过 CHECKPOINTS 提供逗号分隔的多个不同名称 checkpoint，包括最新权重。
```

默认输出新目录 `outputs/lightwam_base_robomimic_square/train_scene_eval_*`。
`run.log` 持续提供 STATUS/DONE，`env_worker.log` 保留仿真子进程日志，`metrics.json` 持续更新。
每条示范与每个模型分别保存 `rollout.gif`、`rollout.npz` 和 `metrics.json`。
GIF 为5Hz策略输入图像，不是完整控制频率视频。断点续跑未实现，失败后使用新输出目录。

## 下一步判据

示范失败先查场景恢复/动力学，不能归因于模型；训练场景成功但普通随机初始化失败，重点查覆盖与闭环鲁棒性。
示范成功但训练场景模型也失败，再考虑闭爪前状态的短段闭环和同状态图像输入对照。
不根据训练集开环低误差直接追加长训或启动 RL。
