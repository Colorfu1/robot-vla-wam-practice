# 模型验证方法：动作、闭环、未来图像与受控干预

供 agent 和实验执行者复用的方法索引。具体运行状态与结果写入
[实验记录](../../experiment_log.md)；待执行任务放入 [plans](../../../plans/README.md)。
本文件不是实验结果，也不意味着列出的旧入口兼容所有 checkpoint。

## 先固定协议

每次记录 checkpoint/hash、数据来源、轨迹与帧号、相机及拼接顺序、像素范围、
自身状态和动作归一化、预测/执行步数、视频采样间隔、控制频率、采样器及噪声种子、
渲染后端、成功判据和时间预算。按 checkpoint 协议运行，不根据文件名猜测。

当前 Square 双视角协议是：agentview 左、腕相机右，各原生224×224，拼接224×448；
预测32个连续控制动作，每次执行前4步；视频为当前帧加未来8帧，
对应控制步偏移0、4、8、…、32。20 Hz控制下，预测范围为1.6秒。
agentview 是外部相机，不应未经核实就称为顶部相机。

## 方法选择

| 要回答的问题 | 方法 | 不能据此断言 |
| --- | --- | --- |
| 是否拟合训练标签 | 真值RGB和自身状态输入，完整采样动作后比较标签 | 闭环能成功或具有泛化能力 |
| 训练场景能否自主完成 | 恢复示教初态/XML后闭环；真值动作回放作对照 | 所有训练场景都成功 |
| 模型在失败时想象了什么 | 下述未来图像预览 | 想象画面导致动作或失败 |
| 视觉输入是否改变闭合行为 | 下述一次性GT图像干预 | 图像预测对动作存在因果控制 |
| 渲染差异是否影响输出 | 同一GT状态，保存RGB/重渲染RGB配对采样 | 单个后端就是低成功率根因 |
| 推理实现是否偏离训练 | 固定输入/噪声，分解条件、VAE、缓存、精度差异 | 单步网络差异等于最终动作误差 |
| 长执行完成抓取后，短重规划是否有利 | 下述同历史切回4步对照 | 已获得通用阶段切换控制器 |

开环至少分开报告前4步与完整预测长度、arm MAE/MSE、夹爪符号准确率、闭合召回、
闭合样本数、逐轨迹结果；不能把动作误差叫作“开环成功率”。
精度对照应跑完完整动作采样过程，不只比较某个去噪时间步。

## 验证一：自主rollout的未来图像

1. 从可追溯初始状态运行策略，保存实际执行动作及恢复所需信息。
2. 在动作执行前的当前观测上做未来预测；不要输入未来真值帧。
3. 动作仍由原始动作推理路径输出。视频预测只用于诊断，不反馈到策略。
4. 将下列画面明确分行，并写出绝对控制步和相对偏移：
   - `ACTUAL`：模拟器真实画面。
   - `POLICY_INPUT`：该次策略实际接收的画面。
   - `PRED`：从该输入生成的未来画面。
   - `DEMO`：示教画面，不能冒充失败rollout的正确未来。
5. 同时保存诊断联合推理动作与实际执行路径动作的差值；两者不等时不得宣称
   视频是实际动作的精确物理预测。

第一张生成帧是条件帧重建，不是未来预测。当前双视角的下一张是t+4而不是t+1。
真实rollout每4步重新规划，因此t+8及更远的真实画面对应后续重新决策；
它与单次32步想象不是固定动作序列下的严格预测误差对照。

检查夹持时查看物体/手指局部、逐帧变化和真实接触/抬升证据。
全图MAE容易被静态背景主导；补充复制当前帧基线和VAE重建基线。
“预测夹住”“发出闭合命令”“实际夹住”“抬起后未掉落”“任务成功”分别记录。

## 验证二：一次性GT前帧RGB干预

目的：在同一失败物理状态上，测试视觉条件改变是否改变夹爪动作及实际夹取。
这不是GT物理状态接管，也不是把生成的未来帧塞回模型。

1. 连续查看示教抓取阶段，选择开始闭合之前的观测帧。动作符号转正只能定位候选，
   不能证明已经抓住。记录输入帧、闭合开始和抬升帧。
2. 选择原始失败rollout里姿态/位置尽量接近的决策点，记录匹配依据与自身状态差。
   自动最近邻只是候选；不能直接沿用旧实验的轨迹16/帧87/步260。
3. 两分支都从同一XML和初态重放相同已执行动作前缀。
   验证分支点状态、自身状态和真实RGB一致；只有积分状态快照不保证控制器状态恢复。
4. 原始分支输入实时RGB；干预分支仅第一次用选中的GT RGB替换。
   当前双相机实验应替换完整双视角拼接图，保持shape、相机顺序和像素范围一致。
   不修改物理状态、自身状态、语言、checkpoint、噪声种子或动作后处理。
5. 两分支执行各自预测的前4步，再恢复各自实时观测自主闭环，使用相同总预算。
   不持续喂GT图像，不强制夹爪动作为+1。
6. 展示分支点的ACTUAL、POLICY_INPUT、PRED与实际后续画面，
   保存首次完整动作/执行动作、夹爪命令、手指状态、接触/抬升和任务成功信息。

建议增加独立的GT RGB＋GT自身状态离线预测面板，但它不属于同物理状态配对实验。
GT图像与真实物理状态可能矛盾；夹爪闭合却没抓住不等于未学会闭合。
即使图像替换同时改变未来预测和动作，也只支持视觉条件影响两种输出，
不证明“生成视频驱动动作”。少量案例是诊断，不是泛化成功率。

## 验证三：长执行抓取后切回4步重规划

目标：区分“抓取阶段需要完成较长动作段”和“抓取之后也必须保持长执行窗口”。
模式为 `Closed-loop diagnostic`，不重新训练，不做新的图像或夹爪指令干预。

### 实验思路

1. 从已完成且通过恢复检查的 `original_execute32` 选择一个或多个已抬升候选决策点；
   选点与阶段门控必须使用同一个高度参照。
2. 每个点都重放同一XML、初态和**已有策略动作**前缀，不逐帧恢复GT状态。
3. 先检查前缀一致性、物体高度及双指接触，再分为继续32步或切回4步重规划。
4. 两侧checkpoint、切换时当前双RGB/自身状态、采样种子和首个32步计划一致。
5. 总预算仍到绝对控制步600；32步对照还必须精确复现已保存的后缀。
6. 每控制步保存物理证据；网页仅展示 `ACTUAL`，不将真实画面标作预测。

### 完整命令与产物

当前固定案例的启动命令见[短线执行计划](../../../plans/2026-10-08-FastWAM抓取后短重规划对照.md)。
当前仅补跑412控制步的执行4/32对照，使用2卡EGL，不是重跑80局评测。
原脚本 `scripts/experiments/rl/run_fastwam_grasp_handoff.sh` 仍固定380/412共4项，
不要直接用它做本次补跑。原运行中止原因与结论边界见
[诊断记录](../../daily/2026-10-09-FastWAM抓取后重规划诊断结论与复现步骤.md)。
直接命令如下（仓库根目录执行）：

```bash
export PYTHONNOUSERSITE=1
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 DIFFSYNTH_SKIP_DOWNLOAD=true
export OMP_NUM_THREADS=2
export OUT="outputs/fastwam_grasp_handoff412_$(date +%Y%m%d_%H%M%S)"
mkdir -p outputs
conda run --no-capture-output -n fastwam-upstream python -u \
  -m robot_practice.experiments.rl.fastwam_execution_window_probe \
  --source outputs/fastwam_dual_visual_checks_20260923_102341 \
  --handoff-source outputs/fastwam_execution_window_probe_20261008_063142/original_execute32 \
  --trajectory 0 --switch-steps 412 --max-steps 600 \
  --gpus 0,1 --output "$OUT"
```

根目录保存 `metrics.json`、`run.log`、`index.html`；每个 `handoff_XXXX_executeK/` 保存：

- `prefix/`、`continuation/`：实际动作及恢复证据，不是示教动作续接。
- `prefix_stage_evidence.npz`：初态至分支点的物体高度、末端位置、手指关节、双指接触。
  即使物理阶段门控失败也保留此文件。
- `stage_evidence.npz`：完整逐控制步物理证据；`plans.npz`：各次32步预测与实际执行长度。
- `actual_5hz.gif`：切换前32步及后续真实画面，带绝对控制步，不生成未来视频。
- `metrics.json`：各项门控、首次张开指令、持续接触丢失、物体高度和任务成功。

### 判断标准与边界

- 门控预先固定：分支点最近5个控制端点均比reset物体高度高至少20毫米，
  且至少3个端点满足robosuite双指接触判据。它是诊断代理指标，不证明稳定抓持。
- 前缀状态/动作/观测恢复及首次预测逐值一致；
  同一切换点两侧输入hash一致；32步后缀对照必须逐值一致。
  任一不通过则停止解释策略差异，先检查恢复证据，不临时放宽门限。
- 比较切回4步是否持续保持夹持、完成搬运/插入，以及何时再次张开或失去接触。
  物体下降或接触丢失也可能是正常放置，必须结合实际GIF和任务成功判据解释。
- 切换后使用实时观测，不输入GT或物理诊断信息；切换时刻来自事后选点，
  成功也仅支持该案例阶段执行策略有效，不等于学会在线识别抓稳，更不证明视频驱动动作。

## 已有入口与兼容性

源码均位于 `src/robot_practice/experiments/rl/`：

- `fastwam_execution_window_probe.py`：从已有双视角capture的同一控制步恢复，
  原始/既有图像干预两类历史各比较执行4、8、16、32步，8卡EGL。
  保持32步预测及采样种子不变，仅改变重规划间隔。前缀及首次预测必须匹配源产物，
  4步基线还需复现源轨迹后缀；不重新注入GT图像，也不生成视频参与控制。
  真实GIF以统一5 Hz保存，手指状态和闭合命令单独记录；是否夹住/掉落需人工复核。
  入口默认轨迹0、控制步124、总600步预算；不把不同历史分支的状态视作相同状态。
  添加 `--handoff-source` 可运行上述抓取后配对续跑；此模式默认切换点380、412，
  默认需要显式传4张GPU，不沿用普通模式默认的8张；单点412应显式传2张GPU。
  只接受兼容的已完成original_execute32产物。候选不合格目前仍会触发整组终止，尚未实现自动跳过。

- `fastwam_dual_visual_checks.py`：当前双视角专用预览与一次性图像干预，
  通过 `fastwam_dual_train_fit_multigpu --visual-checks-only` 启动。
  每次决策均预览9帧，动作仍由原生动作推理执行；输出根目录 `index.html`。
  自动使用首次闭合命令前帧及最近自身状态决策点，预算允许时至少预留32步后续。
  页面含连续20 Hz示教片段供人工检查候选；不把自动候选当作已验证抓取帧。
  每条轨迹重新运行基线，前缀验证通过后分支；不宣称精确复现旧评测文件。
  此入口本地单元测试不替代远端模型/模拟器验证。

- `fastwam_dual_train_fit.py` / `fastwam_dual_train_fit_multigpu.py`：双相机训练集开环与闭环；
  多卡入口复用动态CUDA/EGL映射。
- `fastwam_dual_image_pair.py`：保存图像与重渲染图像的动作配对对照。
- `fastwam_protocol_parity.py`、`fastwam_autocast_action_check.py`：协议分解与完整采样精度对照。
- `fastwam_rollout_video.py`、`fastwam_failure_preview.py`、`fastwam_image_intervention.py`：
  旧单视角视频与干预实现参考。不得直接用于双视角32步checkpoint；
  旧图像干预代码固定生成5帧/4动作且依赖旧capture目录结构。

移植时先读实际入口与checkpoint协议，测试对齐、恢复及图像标签，再给执行命令。
EGL静态导出通过不等于闭环验证通过；成功率为0也不等于渲染崩溃。
长任务必须输出阶段及completed/total，并写持久run.log和运行中metrics。
