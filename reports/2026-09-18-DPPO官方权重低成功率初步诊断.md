# 2026-09-18 DPPO官方权重低成功率初步诊断

## 重要进展

- 用户提供的正式对照中，官方 checkpoint EMA 为 9/80，当前训练 epoch 2000 EMA 为 24/80。
- 较新官方独立 DiffusionEval 读取 model，而历史预训练基类加载器优先 EMA；两种入口不能混称同一种官方权重选择。
- 本地同一官方 checkpoint、同一批 256 个训练窗口、相同采样种子对照：model MSE 0.007851，EMA MSE 0.022979。
- 找到同 checkpoint 的历史 frozen-base 可视化记录 63/150；当时入口代码使用独立 evaluator，但 seed、批次与渲染不同，不能直接作因果比较。
- 下一步远端仅切换官方 checkpoint 的 model/EMA，保持最近的 80 回合协议不变；根因尚未确认，不修改训练或渲染配置。

## 反馈回路与假设

症状：固定官方 state_4000，当前 OSMesa + 20 envs + 400 policy iterations + seed 42，EMA 成功率 11.25%。
快速回路：使用发布 train.npz 的前 100 条全部有效窗口，在 26914 个索引上等距选 256 个；
batch 32，每批 torch seed 为 42 加该批起始索引；官方 DiffusionEval、DDIM 5、augment=False。
仅替换 actor 为同 checkpoint 的 model 或 EMA，strict=True；目标是 normalized 4×7 动作。

按优先级的可证伪假设：

1. 历史 EMA 较弱：若成立，同输入 MSE 和同闭环协议成功率均应较 model 差。
2. 渲染后端差异：若成立，固定 simulator state 的 EGL/OSMesa 图像及动作应显著不同。
3. 初始状态或连续 reset 协议：若成立，按 seed 和 rollout 轮次拆分会显示差异。
4. 预处理/控制配置错误：若成立，逐项数值和环境元数据对照可定位偏差。

## 已测结果

| 权重 | normalized action MSE | arm MSE | gripper sign accuracy |
|---|---:|---:|---:|
| 官方 model | 0.007850906 | 0.002979765 | 0.9892578 |
| 官方 EMA | 0.022978662 | 0.008971856 | 0.9707031 |

这只是训练数据上的开环动作误差，不是闭环成功率或泛化证明。
EMA MSE 约为 model 的 2.93 倍，支持第一假设，但还需要远端闭环单变量实验。
v0.6 的低频 EMA 更新与后续官方修复相符；没有历史 launch manifest，不能断言该机制已经解释本例全部差距。

## 已检查与尚未检查

- 官方 checkpoint 的网络参数可以 strict 加载，无缺失项错误。
- 静态代码路径：训练图片以 uint8 存储，评测 wrapper 将图像恢复为 0–255，ViT 内再除以 255 并减 0.5；没有从代码上发现重复归一化证据。
- 本地版本 robosuite 1.4.1、robomimic 0.3.0、MuJoCo 2.3.7；官方 env metadata 的 robosuite 版本为 1.4.1。
- 尚未测得同一仿真状态下的 EGL/OSMesa 图像差异；尚未核实本轮远端实际模块路径和文件校验值。
- 历史 63/150 是不同 seed/环境组织下的旧记录，不是本轮复现成功率。不能用它证明渲染、权重选择或任何单一因素。

使用新目录，比较新的 result.npz 与已有 EMA 9/80。若原始 model 同样低，再继续逐项验证后端与环境。
