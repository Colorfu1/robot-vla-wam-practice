# Generic Single-Task LIBERO ACT Evaluation Design

## Status

Approved in conversation on 2026-07-22. This design extends and, where the two conflict,
supersedes the fixed-task portions of
`2026-07-20-act-evaluation-design.md`. The existing metric definitions, checkpoint loading
contract, terminal-success handling, and Rerun conventions remain in force unless this
document explicitly changes them.

## Goal

Turn the two ACT evaluation launchers into explicit, single-task evaluators for any task in
the five LIBERO suites supported by the installed LeRobot integration:

- `libero_spatial`;
- `libero_object`;
- `libero_goal`;
- `libero_10`;
- `libero_90`.

One invocation evaluates exactly one zero-based LIBERO `task_id`. Both offline prediction and
closed-loop rollout use the same `(suite, task_id)` identity. Missing offline demonstrations
are prepared automatically, one task at a time, and all important task, policy, data,
download, replay, cache, evaluation, warning, and output information is printed to the user.

The evaluator remains ACT-specific. ACT has no language input, so supporting arbitrary
LIBERO tasks does not make one checkpoint task-general. A checkpoint/task semantic mismatch
is prominently reported but, by explicit product decision, does not block evaluation.

## Non-Goals

This change does not:

- evaluate multiple tasks or a complete suite in one invocation;
- support `libero_100` as an aggregate task-ID namespace;
- add language conditioning to ACT;
- add policies other than ACT;
- add perturbation implementations beyond the existing `none` placeholder;
- accept a standalone `.pth` or `.safetensors` file instead of a complete LeRobot
  `pretrained_model` directory;
- modify files in the installed LeRobot or LIBERO packages;
- push downloaded or converted demonstrations to the Hugging Face Hub;
- commit datasets, checkpoints, Rerun recordings, videos, or other generated artifacts.

## Approved Product Decisions

The following decisions are fixed for this version:

1. `--suite` and `--task-id` are required by both launchers. There is no silent default to
   `libero_object` task 8.
2. One command evaluates one task.
3. Offline evaluation defaults to every available demonstration for the selected task.
4. Offline and closed-loop visualization both default to one episode and can be overridden.
5. Missing demonstrations are downloaded and converted automatically.
6. Download granularity is one upstream task HDF5, not a whole suite.
7. Missing task data is regenerated by replay in LIBERO at 256 x 256, rather than by merely
   resizing the upstream 128 x 128 images.
8. The original HDF5 and converted LeRobot dataset are both retained as reusable caches.
9. An unknown or mismatched checkpoint task produces a warning and recorded metadata, then
   evaluation continues.
10. User-visible progress and paths are mandatory; download, conversion, and task mapping
    must never happen silently.

## Task Identity Contract

Add a shared immutable task descriptor, conceptually:

```python
@dataclass(frozen=True)
class LiberoTaskIdentity:
    suite: str
    task_id: int
    task_name: str
    language: str
    problem_folder: str
    source_relative_path: str
    episode_length: int
```

The descriptor is resolved from the installed LIBERO benchmark registry, not from a second
hand-maintained list of 130 task names. A small local allowlist controls supported suites and
their LeRobot episode limits:

| Suite | Valid task IDs | Default episode length |
|---|---:|---:|
| `libero_spatial` | 0-9 | 280 |
| `libero_object` | 0-9 | 280 |
| `libero_goal` | 0-9 | 300 |
| `libero_10` | 0-9 | 520 |
| `libero_90` | 0-89 | 400 |

Resolution validates the suite, instantiates its benchmark, validates `task_id` against the
actual installed task count, and reads `task.name`, `task.language`, and
`task.problem_folder`. The upstream file is
`<suite>/<task.name>_demo.hdf5` in `yifengzhu-hf/LIBERO-datasets`.

`libero_100` is rejected with an actionable message asking the caller to choose either the
`libero_10` or `libero_90` namespace. This avoids two overlapping ID systems for the same 100
tasks and matches the installed LeRobot environment's five-suite episode-limit contract.

## Architecture

Keep launchers thin and put reusable behavior under `src/robot_practice/`:

```text
src/robot_practice/evaluation/
├── common.py                  # existing checkpoint/output/serialization helpers
├── metrics.py                 # existing metric definitions
├── rerun_visualization.py     # existing Rerun logging
├── libero_tasks.py            # task identity and suite validation
├── libero_dataset_cache.py    # discovery, download, replay, conversion, cache manifests
├── offline_act.py             # generic single-task teacher-forced evaluation
└── libero_act.py              # generic single-task closed-loop evaluation

scripts/experiments/act/
├── eval_offline.sh
└── eval_libero.sh
```

`libero_tasks.py` has no dataset or policy dependency beyond the installed LIBERO benchmark.
`libero_dataset_cache.py` does not perform model inference. `offline_act.py` asks the cache
module for a resolved dataset selection and then retains ownership of prediction and metrics.
`libero_act.py` uses the shared task descriptor but never downloads demonstrations.

## Command Interfaces

### Offline

```bash
scripts/experiments/act/eval_offline.sh \
  --policy-path=<pretrained_model> \
  --suite=libero_object \
  --task-id=8
```

Required arguments:

- `--policy-path PATH`: complete local LeRobot ACT `pretrained_model` directory;
- `--suite NAME`: one of the five supported suite names;
- `--task-id INTEGER`: zero-based ID within the chosen suite.

Optional arguments:

- `--episodes ID [ID ...]`: dataset-native episode indices; omitted means all episodes for
  the selected task;
- `--dataset-root PATH`: an exact existing LeRobot dataset override. When supplied, it must
  contain an unambiguous match for the selected task. Failure is explicit and automatic
  download does not write into or fall through from this user-selected root;
- `--batch-size INTEGER`: positive, default 1;
- `--num-visualized-episodes INTEGER`: default 1, valid from zero through the number of
  selected episodes;
- `--output-dir PATH`: exact new output directory;
- `--max-frames INTEGER`: positive global smoke/debug bound;
- `--rebuild-dataset-cache`: rebuild a task-local generated cache instead of reusing it;
- `--no-open-viewer`: save the Rerun recording without opening the viewer.

An explicit `--episodes` list is validated after task-to-dataset mapping. In the existing
combined 40-task dataset these are global indices such as the A-Sanity episode IDs. In a
generated single-task dataset they start at zero. The evaluator prints the dataset root and
episode namespace before running so this distinction is visible.

`--rebuild-dataset-cache` does not mutate the existing combined 40-task dataset and does not
delete the raw HDF5. If the combined dataset already satisfies the request, the flag is
reported as not applicable and that source is still reused. Supplying `--dataset-root`
together with `--rebuild-dataset-cache` is a parser/configuration error: an explicit root is
user-managed input, while the rebuild flag is only allowed to replace the evaluator's
task-local generated cache.

### Closed Loop

```bash
scripts/experiments/act/eval_libero.sh \
  --policy-path=<pretrained_model> \
  --suite=libero_object \
  --task-id=8
```

Required arguments are the same policy path, suite, and task ID. Existing optional arguments
remain:

- `--n-episodes INTEGER`, default 20;
- `--num-visualized-episodes INTEGER`, default 1;
- `--perturbation NAME`, default and only implemented value `none`;
- `--seed INTEGER`, default 1000;
- `--output-dir PATH`;
- `--max-steps INTEGER`, bounded by the selected suite's episode length;
- `--no-open-viewer`.

Both Python parsers accept standard argparse `--name=value` and `--name value` forms. The
shell launchers continue to forward arguments unchanged through `conda run`.

## Required User-Facing Output

Use normal logging levels with stable bracketed stage prefixes. The exact whitespace is not
an API, but the facts below are required.

Every run prints task and checkpoint identity before expensive work:

```text
[Task] suite: libero_object
[Task] task_id: 8
[Task] name: pick_up_the_chocolate_pudding_and_place_it_in_the_basket
[Task] language: pick up the chocolate pudding and place it in the basket
[Policy] checkpoint: /absolute/path/to/pretrained_model
[Policy] checkpoint task: unknown
[Warning] Cannot verify checkpoint/task match; evaluation will continue.
```

A reuse of the existing combined dataset prints:

```text
[Dataset] source: existing LeRobot dataset
[Dataset] root: /absolute/path/to/datasets/lerobot/lerobot/libero
[Dataset] mapped task_index: 29
[Dataset] episode namespace: combined-dataset global indices
[Dataset] selected episodes: 50 (all demonstrations)
```

A cache miss prints metadata before network or replay work:

```text
[Dataset] No converted demonstrations found for this task.
[Download] repository: yifengzhu-hf/LIBERO-datasets
[Download] revision: <resolved commit SHA>
[Download] file: libero_90/<task_name>_demo.hdf5
[Download] size: 742 MiB
[Download] destination: /.../datasets/raw/libero/libero_90/<file>
[Download] free disk space: 318 GiB
[Download] Raw and converted data will remain cached.
[Replay] output: /.../datasets/lerobot/libero_tasks/libero_90/task_003
[Replay] source camera shape: 128x128; regenerated shape: 256x256
[Replay] source control metadata: 20 Hz; output dataset contract: 10 Hz
```

Replay emits progress and a final summary:

```text
[Replay] source demonstrations: 50
[Replay] successful: 47
[Replay] failed: 3
[Replay] filtered no-op steps: 186
[Replay] generated frames: 8420
[Replay] report: /.../replay_report.json
[Dataset] cache ready: /.../task_003
```

Before inference, each evaluator prints mode, selected counts, visualization count, policy
chunk settings, perturbation, output path, and whether the run is formal or smoke. On
completion it prints primary metrics and absolute paths to every artifact it produced.
Exceptions include the failed stage, relevant paths, whether a reusable raw download exists,
the `.incomplete` or replay-report path when applicable, and a directly runnable retry
command. A stack trace may follow, but it is not a substitute for this message.

## Existing 40-Task Dataset Resolution

The current combined dataset has 40 language rows but does not store LIBERO suite/task IDs,
and its `task_index` ordering differs from simulator task IDs. Numeric IDs must never be
treated as interchangeable.

Resolution uses the selected benchmark task's exact normalized language and the dataset's
`meta/tasks.parquet`:

1. normalize surrounding whitespace without rewriting words;
2. find rows whose task string exactly equals the benchmark language;
3. accept reuse only if there is exactly one match;
4. scan Parquet `task_index` and `episode_index` columns to enumerate all matching episodes;
5. validate that every selected episode contains only that dataset task index.

If there are zero or multiple matches, the combined dataset is considered unavailable for
that task. The resolver prints the reason and uses a task-local generated cache. It must not
guess from a numeric task index or an ambiguous language string. A small derived index may be
cached for speed, but it is generated data and must be invalidated when source metadata or
data file identities change.

For the current A-Sanity task, the validated identity remains:

```text
suite=libero_object
task_id=8
dataset task_index=29
language="pick up the chocolate pudding and place it in the basket"
```

## Raw Download Contract

The upstream source is the dataset repository used by the installed LIBERO downloader:
`yifengzhu-hf/LIBERO-datasets`. The downloader first queries repository metadata, resolves
`main` to an immutable commit SHA, verifies that the exact task file exists, obtains its size
and LFS identity, and prints them. The actual download is pinned to that resolved revision.

Only `<suite>/<task.name>_demo.hdf5` is requested. Suite-wide `snapshot_download` is not used.
The destination is:

```text
datasets/raw/libero/<suite>/<task.name>_demo.hdf5
```

Before download, print free disk space and reject an obviously impossible download. Use a
conservative preflight requirement of the missing raw bytes plus conversion headroom equal to
`max(4 * raw_file_size, 5 GiB)`. A rebuild needs the same conversion headroom because the old
valid cache stays in place until its replacement passes validation. Print the estimated
requirement and free space. Hugging Face's resumable cache may be used internally, but the
final user-facing HDF5 path above must be stable and printed.

The raw file is validated before replay:

- root group `data` exists;
- task language in `data.attrs["problem_info"]` matches the selected task;
- all demonstrations have `actions[T, 7]`, `states`, `robot_states`, and required metadata;
- if observation arrays are present, their known upstream schema is checked and recorded;
- action and state arrays contain only finite values;
- every demonstration has a positive, internally consistent length.

The raw source is expected to contain 128 x 128 `agentview_rgb` and `eye_in_hand_rgb`, 6D
`ee_states`, 2D `gripper_states`, and 7D actions, but replay derives observations from the
current simulator rather than trusting or resizing those images.

## Replay and Conversion Contract

Generated data lives at:

```text
datasets/lerobot/libero_tasks/<suite>/task_<task_id:03d>/
```

The converter uses the installed LIBERO benchmark task and the source demonstration's first
simulator state. For every raw demonstration, it:

1. resets a 256 x 256 off-screen, dual-camera environment for the selected task;
2. restores the demonstration's initial simulator state;
3. executes ten standard LIBERO no-op settling steps;
4. iterates source actions in order;
5. filters a no-op when the first six action dimensions have norm below `1e-4` and the
   gripper action equals the previous kept gripper action; for the first action, only the
   first-six-dimension criterion applies;
6. before executing each kept action, records both cameras and constructs
   `eef_position[3] + eef_axis_angle[3] + gripper_qpos[2]`;
7. rotates each image 180 degrees by flipping height and width, matching the current LeRobot
   LIBERO processor convention;
8. executes the unchanged 7D relative action;
9. keeps the episode only if the simulator reports task success during the replay.

Each failure records the source demonstration ID, last completed action index, failure class,
and message in `replay_report.json`. One failed demonstration does not abort the remaining
replays. Zero successful replays is a hard failure and no valid converted cache is published.

The resulting LeRobot v3 single-task dataset uses:

```text
robot_type: panda
fps: 10
observation.images.image:  video, uint8, [256, 256, 3]
observation.images.image2: video, uint8, [256, 256, 3]
observation.state:         float32, [8]
action:                    float32, [7]
task:                      selected benchmark language
```

Source environment metadata currently reports 20 Hz while the existing LeRobot dataset and
experiment contract use 10 Hz. This difference is printed and recorded. The converter follows
the approved 10 Hz output contract and does not claim that no-op-filtered transitions form a
physically uniform source timeline. This limitation must also appear in the generated source
manifest so offline temporal metrics are interpreted correctly.

Write `source_manifest.json` alongside the normal LeRobot metadata. It contains at least:

- schema and converter versions;
- suite, task ID, task name, language, and problem folder;
- upstream repository, immutable revision, relative path, file size, and LFS/checksum
  identity;
- upstream dataset license (`CC BY 4.0`) and attribution URL;
- raw and output observation/action contracts;
- source and output frequency metadata;
- LeRobot, LIBERO, Robosuite, MuJoCo, Python, and converter versions;
- source, successful, failed, and output episode/frame counts;
- filtered no-op count;
- creation timestamp and replay-report path.

## Cache Concurrency, Atomicity, and Recovery

Use a per-task advisory file lock outside the final dataset directory. A second process prints
that it is waiting, then rechecks the cache after acquiring the lock. It must not perform a
duplicate download or replay.

Replay reports have a persistent task-owned location even when no valid dataset can be
published:

```text
datasets/lerobot/libero_tasks/replay_reports/<suite>/task_<task_id:03d>/<timestamp>/
└── replay_report.json
```

A successful cache also contains a copy of its replay report and references the persistent
report from `source_manifest.json`.

Download and conversion state are separate:

- a complete valid raw HDF5 is reusable even when conversion fails;
- conversion occurs in a uniquely named sibling temporary directory containing an
  `.incomplete` marker;
- LeRobot metadata, frame counts, feature shapes, task language, episode counts, video
  readability, source manifest, and replay report are validated before publication;
- successful publication removes `.incomplete` and atomically renames the temporary directory
  to the final cache path;
- interruption leaves no directory that can be mistaken for a valid cache;
- the next run reports and removes stale task-owned temporary conversion directories before
  rebuilding;
- unrelated user paths are never removed.

`--rebuild-dataset-cache` acquires the same lock, creates and validates a replacement first,
then swaps it into place without touching the raw HDF5. If replacement fails, the previous
valid cache remains available and is reported.

Cache validation requires the supported `source_manifest.json` schema version and a converter
version declared compatible by local code. The initial cache schema and converter compatibility
version are both `1`. A missing or incompatible manifest is never silently reused. Without
`--rebuild-dataset-cache`, fail with the cached and required versions plus an exact retry
command containing that flag. With the flag, build and validate a replacement using the normal
preserve-old-until-swap procedure.

## Offline Evaluation Flow

`OfflineEvaluationConfig` gains required `suite` and `task_id`, optional `episodes`, optional
`dataset_root`, `num_visualized_episodes`, and `rebuild_dataset_cache`. Its episode default is
`None`, meaning resolve all demonstrations for the selected task.

The evaluator:

1. resolves and prints task identity;
2. validates the complete ACT checkpoint and reports best-effort task identity;
3. resolves an explicit dataset override, the existing combined dataset, or the task cache;
4. downloads/replays only when neither reusable dataset source exists;
5. resolves all task episodes and then applies an explicit `--episodes` filter;
6. validates the ACT action delta timestamps against the resolved dataset's 10 Hz metadata;
7. runs teacher-forced chunk prediction and computes metrics over every selected frame;
8. logs images/actions to Rerun only for the first `num_visualized_episodes` selected episodes;
9. writes all frame predictions to Parquet regardless of visualization selection;
10. atomically marks the result complete and prints metrics/artifact paths.

The teacher-forced interpretation is unchanged: open-loop errors measure imitation on fixed
demonstration observations and cannot establish simulator success.

Offline output includes overall and per-action open-loop errors, valid-horizon chunk errors,
predicted and target action TV/Jerk with short metric annotations, model-query latency, and
the selected data/task identity. Existing padding rules remain unchanged.

## Closed-Loop Evaluation Flow

`LiberoEvaluationConfig` gains required `suite` and `task_id`. `make_libero_config()` accepts
the resolved task descriptor and uses its suite-specific episode length. The rest of the
approved single-environment rollout contract remains unchanged:

- relative 7D control;
- 256 x 256 dual-camera `pixels_agent_pos` observations;
- 8D state from `LiberoProcessorStep`;
- deterministic seed and init-state sequence;
- formal success only from terminal `final_info.is_success`;
- all episodes contribute to metrics;
- only the visualization prefix produces Rerun images and MP4 files;
- reduced `--max-steps` runs are marked smoke and do not report formal success rate.

Closed-loop output includes success rate, rewards, executed-action TV/Jerk, gripper toggles,
policy-step latency, neural-network query latency, suite/task identity, and per-episode
termination details. `--perturbation=none` is printed and recorded; other perturbation values
still fail explicitly in this version.

## Checkpoint Compatibility and Task Matching

Structural compatibility is strict. Evaluation stops before inference unless the loaded ACT
checkpoint has:

- 7D action output;
- 8D state input;
- the two expected camera inputs;
- processor configuration and normalization state files required by the complete checkpoint
  contract.

Semantic task matching is best effort. Inspect checkpoint-local training and initialization
manifests when present, including dataset repo/root and episode selections. Resolve those
episodes to a LIBERO identity only when evidence is unambiguous. Record one of:

```text
match
mismatch
unknown
```

`match` is informational. `mismatch` and `unknown` emit `[Warning]` messages explaining that
ACT has no language input, then continue. The status, evidence, selected task, and message are
written to `run_config.json` and the metric summary. No task identity is inferred merely from
state/action dimensions.

## Output Layout and Artifacts

Default outputs are task-namespaced:

```text
<training-run>/eval/offline/<suite>/task_<task_id:03d>/<timestamp>/
<training-run>/eval/libero/<suite>/task_<task_id:03d>/<timestamp>/
```

An explicit `--output-dir` remains an exact leaf that must not already exist. Existing
timestamp and `.incomplete` behavior remains.

Offline artifacts:

```text
run_config.json
metrics.json
predictions.parquet
prediction.rrd
.complete
```

Closed-loop artifacts:

```text
run_config.json
metrics.json
eval_info.json
rollouts.parquet
rollout.rrd
videos/episode_XXX.mp4     # visualization prefix only
.complete
```

`run_config.json` gains the resolved task descriptor, task-match status/evidence, data source,
dataset task index when applicable, selected episodes, source-manifest path when applicable,
and visualization selection. Parquet rows retain dataset-native episode IDs and gain suite and
LIBERO task ID where doing so does not break the existing schema's meaning. Schema metadata is
versioned when columns change.

## Error Handling Matrix

| Condition | Behavior |
|---|---|
| Unknown suite or out-of-range task ID | Fail before policy/data work; print valid values |
| `libero_100` supplied | Fail; direct user to `libero_10` or `libero_90` |
| Incomplete/non-ACT checkpoint | Fail using the existing complete-checkpoint contract |
| Structural state/action/camera mismatch | Fail before inference |
| Checkpoint task mismatch/unknown | Warn, record, continue |
| Explicit dataset root lacks task | Fail; never silently use another root |
| Explicit dataset root plus rebuild flag | Fail; user roots are never rebuilt |
| Combined dataset mapping ambiguous | Print reason and use task-local cache |
| Upstream file missing | Fail with repository/revision/path and retry guidance |
| Insufficient disk space | Fail before download with required/free sizes |
| Interrupted download | Preserve resumable upstream cache; do not publish raw file |
| Invalid HDF5/schema/language | Fail before replay and identify the field |
| Individual replay failure | Record and continue remaining demonstrations |
| All demonstrations fail replay | Fail; retain raw HDF5 and replay report |
| Interrupted conversion | Leave only task-owned incomplete temp state; rebuild next run |
| Existing valid cache | Print cache hit and reuse |
| Generated cache manifest version incompatible | Fail with explicit rebuild command |
| Concurrent preparation | Print wait state, lock, then recheck cache |

## Tests

Default tests must not download large remote artifacts.

### Unit tests

- resolve all five suite names and all 130 installed task IDs;
- reject unknown suites, `libero_100`, negative IDs, and upper-bound violations;
- verify suite episode limits and upstream relative paths;
- map fixture/current task-language metadata without treating numeric ID systems as equal;
- reject zero-match and ambiguous-match dataset metadata;
- validate optional/all episode selection and dataset-native index rules;
- validate raw HDF5 fixture schema, dimensions, finite values, and language identity;
- test exact no-op filtering behavior;
- test 8D state construction and 180-degree image rotation;
- test source-manifest and replay-report schemas;
- test cache hit/miss/rebuild, stale temp cleanup, lock recheck, and previous-cache preservation;
- reject explicit dataset roots combined with the rebuild flag;
- reject incompatible cache schema/converter versions and print an exact rebuild command;
- test download metadata, disk preflight, and failure messages with a fake Hub client;
- test checkpoint `match`, `mismatch`, and `unknown` reporting;
- test suite/task output paths and required stage-prefixed user messages.

### Evaluation interface tests

- both parsers require `--suite` and `--task-id`;
- offline episodes default to all and visualization defaults to one;
- explicit episodes and visualization bounds are validated after resolution;
- arbitrary suite/task values reach both dataset and environment factories;
- closed-loop max-step validation uses the selected suite's limit;
- all existing success, timing, schema, and smoke/formal invariants continue to pass.

### Local integration tests

- use the existing 40-task dataset, when available, to verify
  `libero_object/task_id=8 -> task_index=29` and the A-Sanity episode set;
- run a bounded offline prediction without network access;
- run the existing one-step LIBERO environment smoke test with generic task arguments;
- build a tiny LeRobot v3 dataset through a fake replay environment and reopen its videos and
  metadata.

### Explicit network/simulator preparation test

A separately marked, manually invoked test may download one real task HDF5 and replay a small
bounded subset. It prints expected disk/time impact first and is never part of the normal test
suite or CI.

Before handoff, run Ruff, the focused evaluation/cache tests, the full repository tests, and
the repository smoke checks when dependency changes require them.

## Acceptance Criteria

The feature is complete when:

1. both launchers require and accept any valid `(suite, task_id)` among the 130 tasks;
2. closed-loop environment construction uses the requested task and correct episode limit;
3. offline evaluation reuses the current 40-task data when identity is unambiguous;
4. a missing task causes only its HDF5 to be downloaded, replayed, validated, and cached;
5. a second invocation reports a cache hit and performs no download or replay;
6. generated data matches the 8D state, 7D action, two-camera 256 x 256 LeRobot v3 contract;
7. offline metrics cover all task demonstrations by default while visualization covers one;
8. checkpoint task uncertainty/mismatch warns and continues, while structural mismatch fails;
9. the terminal tells the user what task, policy, data, work, warnings, metrics, and paths are
   involved at every material stage;
10. no generated artifact is committed and installed dependencies are not patched;
11. focused and full tests pass.
