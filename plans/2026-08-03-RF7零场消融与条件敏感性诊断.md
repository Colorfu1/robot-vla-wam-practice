## 目标

在花掉任何 rollout 预算之前回答一个问题：**RF7 的 route field 通道到底有没有被模型读取。**

做法是固定 observation、固定 Diffusion 初始噪声与反向噪声流，只替换 commanded route，
比较 action chunk 的差异。全部 8 个 checkpoint 都测，不只测选中的那一个 —— 因为选模
本身无法区分"读了路线"和"只读了 observation"，需要独立信号。

## 执行步骤

### 1. 实现诊断入口

现有的 `eval_route_field.sh --gate-only` 需要一个已完成的 `--selection-dir`，只能测
选中的单个 checkpoint，不满足"全部 8 个都测"的要求。需要新增一个从**训练 run 目录**
发现 checkpoint 的入口，接口与 `select_route_field_checkpoints.sh` 对齐：

```text
模块  robot_practice.experiments.pusht_diffusion.route_field_condition_ablation
脚本  scripts/experiments/pusht/ablate_route_field_condition.sh

--bc-run=DIR / --diffusion-run=DIR   至少提供一个
--route-manifest=FILE
--dataset-root=DIR
--split=development|audit            默认 development
--num-inference-steps=N              默认 100，与评测协议一致
--num-gpus=N                         默认 1；>1 时按 checkpoint 并行，--device 仅单卡可用
--device=cuda:N                      默认 cuda:0（单卡）
--output-dir=DIR
--overwrite / --print-command
```

对每个 checkpoint × 每条 episode，取 dataset 中间帧作为固定 observation，五个条件共用
同一份初始噪声与反向噪声流：

| 条件 | 定义 | 作用 |
| --- | --- | --- |
| `oracle` | episode 自己的 GT macro route | 参考基线 |
| `zero` | 全零 `[4,7,7]` 场 | 消融：route 通道用没用 |
| `reversed` | 同格逆序（occupancy 逐格相同） | 顺序/方向通道用没用 |
| `shuffled` | 另一条 episode 的真实路线 | 分布内的错误路线对照 |
| `observation_swap` | 保持 oracle route，换成另一条 episode 的 observation | **尺度参照**：输入变化本来能造成多大差异 |

`shuffled` 与 `observation_swap` 的配对规则必须确定可复现：序号 `i` 的 episode 取序号
`(i + n // 2) mod n` 的路线 / observation。

单格路线无法逆序（dev 有 1 条），该 episode 跳过 `reversed`，其余条件照常。

### 2. 运行诊断

```bash
bash scripts/experiments/pusht/ablate_route_field_condition.sh \
  --diffusion-run=outputs/pusht_diffusion/pilot/route_field_7x7/training/route_field_diffusion \
  --route-manifest=outputs/pusht_diffusion/pilot/route_field_7x7/sidecar/route_manifest.json \
  --split=development \
  --device=cuda:0
```

规模：8 checkpoint × 20 episode × 5 条件 = 800 次 DDPM-100 采样，单卡分钟级到十分钟级。
纯前向，无 rollout，无渲染。

## 判断标准

**以下阈值在看到任何数字之前写死，执行后不得修改。**

差异统一用**去归一化后的世界坐标**度量，主指标是每步位移差的均值
`mean_step_l2 = mean_t || a_t^cond − a_t^oracle ||`，单位是 PushT 像素。参照尺度：
一个 7×7 网格格子 ≈ 73 px，T 块外廓 ≈ 120 px，所以 1 px 不到一个格子的 1.5%。

| 判据 | 阈值 | 结论与行动 |
| --- | --- | --- |
| `zero` 的 `mean_step_l2`，**全部** 8 个 checkpoint | < 1.0 px | route 通道**未被使用**。停止 RF7 闭环计划，转训练侧 |
| `reversed` 的 `mean_step_l2`，**全部** 8 个 checkpoint | < 1.0 px | 顺序/方向通道**未被使用**（occupancy 仍可能被用）。同上 |
| `reversed / observation_swap` 比值，**最佳** checkpoint | < 0.05 | route 影响相对 observation 可忽略。同上 |
| 上述任一判据在某 checkpoint 上明显超过阈值 | —— | 继续执行 RF7 闭环计划，并把该 checkpoint 的敏感性作为选模的额外依据 |

绝对阈值与比值判据同时给出。**两者结论不一致时记为 inconclusive**，不得只挑支持某一
方向的那个来报。

### 解读必须遵守的不对称性

- `zero` 距离 ≈ 0 → **强结论**，route 通道确定没被读取。
- `zero` 距离很大 → **不能下结论**。全零场本身是 OOD 输入，模型从未见过，距离大也可能
  只是"零场很怪"。这是 `reversed` 与 `shuffled` 存在的理由：它们在 occupancy 或路线形状
  上留在分布内。
- `reversed` 距离大 → 只说明顺序/方向通道**被读取**，**不**说明被正确使用。方向是否正确
  只能由闭环的带符号读数回答，不在本计划范围内。

### 附带产出

按 checkpoint 画出敏感性随训练步数的变化。如果敏感性先升后降，说明模型早期用过 route
后期转向记忆 observation —— 这会直接影响选模该取哪一步，成本为零，顺手记录。

## 风险与停止条件

- **不要用 chunk 距离的大小当好坏判据。** 它奖励"对输入敏感"而不是"按指令正确响应"。
  一个把 route field 当 episode 指纹记忆的模型（train 有 83/165 条路线全局唯一）在
  `reversed` 下同样会产生非零距离 —— **闸门可能因为错误的原因通过**。本计划只回答
  "用没用"，不回答"用得对不对"。
- `num_inference_steps` 保持 100，与评测协议一致。改小虽然更快，但会让本诊断与后续
  闭环结果不可直接对照。
- `observation_swap` 换掉了 observation，因此它的差异包含了状态差异，只能作为**上界
  尺度参照**，不能解释成"route 应该造成这么大差异"。
- 若某 checkpoint 加载失败或 `validate_route_field_policy` 报错（`route_grid_size != 7`
  等），先查该 checkpoint 的 `config.json` 再继续，不要跳过后静默汇总。
