## 目标

`episodes.parquet`）覆盖的 task_id 只有 `[1, 4, 8]`，而 7 个背景闭环任务是
`[0, 2, 3, 5, 6, 7, 9]`，**交集为空**。B0 的 0.8714 与 C1 的 96.7% 是在不同任务集上得的，
两者之间不含任何关于回退的信息。

灾难性遗忘是微调最常见的失效模式。本计划让「C1 在背景任务上有没有回退」成为可陈述的结论——
但受 B0 逐 episode 记录丢失的限制，只能做逐任务的非配对比较，结论的精度有限（见风险段）。

## 执行步骤

### 1. 让背景 test 入口接受任意策略

`b0_test_evaluation.py` 现在只接受 `--run-dir` / `--selection-dir`，并强制从
`selected_checkpoint.json` 读取 winner、校验 `split_sha256` 与
`selection_set=background_validation`（第 70–106 行）。C1 的 selection 是
`target_validation`，用不了这个入口。

改法：增加 `--policy-path=DIR` 与 `--model-label=LABEL` 两个参数。

- 两者同时给出时，跳过 selection 溯源校验，直接用该策略；`--run-dir` 退化为只提供 split 与
  默认输出位置。
- 仍然强制：7 个背景任务、每任务 30 个 `test_init_state_ids`、`env_seed=1000`、
  `policy_seed=2000`、`n_action_steps=10`、300 步、`7 × 30 = 210` 条。这些是可比性的前提，
  不接受覆盖。
- `--model-label` 必填且写进 manifest 与结果，用于区分同一目录下的多个策略。
- 不给 `--policy-path` 时行为完全不变（仍走 B0 的 selection 溯源），保证 B0 侧可复现。

### 2. 补齐逐 episode 记录

现有 B0 背景 test 只输出聚合与逐任务成绩，没有 `episodes.parquet`。本步新增逐 episode 落盘，
字段与目标协议评测的 `episodes.parquet` 对齐：`task_id`、`init_state_id`、`episode_index`、
`seed`、`num_steps`、`success`、`termination_reason`。

B0 侧已无逐 episode 记录可配对，因此这一步对本计划的直接作用有限；它的价值在于让 C2/C3 以及
将来任何重跑都能做配对分析，不必再吃一次"产物丢了就只能比聚合"的亏。

### 3. 跑 C1 背景 test

```bash
bash scripts/experiments/smolvla_libero/eval_b0_test.sh \
  --run-dir=outputs/smolvla_libero/pilot/b0_domain_adaptation_offline \
  --policy-path=outputs/smolvla_libero/pilot/c1_default_non_peft/checkpoints/selected/pretrained_model \
  --model-label=c1_selected \
  --num-gpus=8 \
  --libero-assets-dir=datasets/raw/libero_assets \
  --output-dir=outputs/smolvla_libero/eval/background_regression/c1_selected
```

`--run-dir` 仍指向 B0 只是为了取同一份 split，不代表用 B0 的权重。

### 4. 逐任务非配对比较

B0 侧只有逐任务的成功数，因此比较粒度是任务，不是 episode：

- 逐任务对比表：B0 记录值（30/27/15/27/26/30/28）对 C1 实测值，附每任务的差值；
- 合计对比：B0 183/210 对 C1 实测；
- 每任务用 Fisher 精确检验（30 对 30 的非配对两比例），并同时给出未校正与 Holm 校正后的 p 值；
- C1 侧的失败终止原因分布（B0 侧无逐 episode 记录，无法对比）。

**不要使用 McNemar**——它要求配对数据，这里没有。也不要把逐任务差值直接当作回退幅度：30 次
试验下 ±3 条即约 10 个百分点。

### 5. 协议一致性核对

C1 这次运行的 manifest 必须使用与 B0 当时相同的冻结协议：`split_sha256`
`ec4b1d633cf3776d…`、`env_seed=1000`、`policy_seed=2000`、`n_action_steps=10`、
每任务 30 个 `test_init_state_ids`、`total_rollouts=210`。入口已强制这些值不可覆盖
（实测 `--env-seed` / `--policy-seed` / `--n-action-steps` 偏离即拒绝），本步只做记录核对。

## 判断标准

**执行前写死。看到数字之后不得修改。**

| 判据 | 阈值 | 不满足时怎么办 |
| --- | --- | --- |
| 工作量 | C1 一次 `7 × 30 = 210` 条，`status=complete` | 修/重跑 |
| 协议一致性 | 步骤 5 所列字段与 B0 当时的冻结值一致 | 停止，查清后重跑 |
| 使用的 init states | 恰好是 7 任务各 30 个 `test_init_state_ids` | 停止 |
| C1 权重溯源 | sha256 `0b52709340121632…`，`selected_checkpoint.json` 为 step 30000 / `target_validation` | 停止，不得用其他 step 顶替 |
| 逐 episode 记录 | C1 产出 210 行、含 `task_id` 与 `init_state_id` | 修实现（供 C2/C3 与将来重跑配对用） |
| 回退判定 | 以逐任务差值与 Fisher 精确检验（含 Holm 校正）陈述，**不设"必须无回退"的通过门槛** | —— |
| 统计口径 | 不得使用 McNemar 或任何要求配对的检验 | 修分析实现 |
| 一次性 | C1 评测只跑一次；看过结果后不得加 seed、改 horizon 或换 checkpoint | 违反即整份结果作废 |
| 不给 `--policy-path` 时的旧行为 | 与改动前一致（仍校验 B0 selection 溯源） | 修实现 |

**本计划不预设结论。** 回退、无回退、甚至背景任务变好，三种都是合法结果，照实记录。发现回退
不得回头改 C1 的训练配置或选模判据——那属于下一轮设计，另起计划。

## 风险与停止条件

- **统计功效受限，这是本计划已知且接受的代价。** B0 的逐 episode 记录已丢失且不重跑，因此只能
  做逐任务的非配对比较。每任务 30 次试验下 ±3 条就是约 10 个百分点，小幅回退无法与随机波动
  区分。结论只能陈述为「未观察到明显回退」或「观察到某任务显著下降」，不能给出精确的回退幅度。
- **B0 基线来自文档记录，不是本次实测。** 数字取自 `reports/experiment_log.md` 与
  `reports/guides/smolvla_libero/02_b0_domain_adaptation.md`；原始产物已不可校验。报告里必须
  写明这一点，不得让读者以为两组成绩是同一批次跑出来的。
- **C1 只训练了 action expert 与 state projection**（`freeze_vision_encoder=True`、
  `train_expert_only=True`），VLM 主干与视觉编码器冻结。这在先验上减小遗忘风险，但不排除——
  action expert 正是决定动作的部分，113 条示范完全可能把它拉偏。不要拿冻结边界当作"必然
  不会回退"的理由。
- **背景任务的指令与目标任务不同**，C1 训练时只见过三条目标 canonical 指令。若背景任务成绩
  大幅下降，需要区分是「动作能力退化」还是「对背景指令的响应退化」——后者可用 prompt swap
  风格的诊断进一步分解，但那超出本计划。
- 210 条 300 步 rollout 的评测量不小，务必 `--num-gpus=8` 并支持 `--resume`。
