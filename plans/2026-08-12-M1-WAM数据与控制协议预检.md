# 2026-08-12 M1-WAM 数据与控制协议预检

## 状态

`done`：baseline、failed-only repair、final live RGB replay、D_core、LeRobot 数据、state banks
和最终 frozen protocol 均已通过 gate。

## 固定协议

- 任务：只保留 ManiSkill3 `StackCube-v1`；`PlugCharger-v1` 不进入 M1-W。
- 后端：`physx_cuda`，20 Hz，`pd_ee_delta_pose`，原生 7D action。
- episode identity：`env_states[0]` 的 `start_state_fingerprint`，量化容差 `1e-4`；seed、HDF5 group 编号和执行顺序不是 identity。
- 视觉输入：两路 `128×128×3` RGB 加 `qpos/qvel` 18D；不得包含 privileged `extra` 或 `sensor_param`。
- formal horizon：500；action chunk 合同继续由 config 固定为 `2/16/4` 与 `2/16/8`。

## 正式三阶段数据链

### 1. Baseline replay

输入 GPU-native 7D action source，实际调用 GPU `env.step`。只记录 action、success、reward 和
live `env_states`，不保存 RGB；允许出现失败，失败 episode 进入下一阶段。

### 2. Failed-only EE repair

只读取 baseline 末端失败 episode。以原轨迹 TCP reference 为目标，在线计算并发送
`pd_ee_delta_pose`；实际执行过程中保存修复后的 EE action、RGB、qpos/qvel、env_states、
success 和 tracking diagnostics。所有失败 episode 必须修复成功，否则停止。

### 3. Final live RGB replay

按 start-state fingerprint 合并 baseline 成功 action 与 repair 成功 action，不按 seed 猜身份。
对合并 action 再做一次真实 GPU replay，`obs_mode="rgb"`，每次 `env.step` 同步保存 RGB、
qpos/qvel、env_states、action、success。最终必须完整覆盖 source 且每条
`success_at_end=true`；只有该 H5 可进入 D_core。

## 执行入口

先保留唯一的 GPU-native 7D source 并清理旧派生产物：

```bash
bash scripts/experiments/maniskill/prepare_stackcube_live_rgb_source.sh
```

本地 GPU smoke：

```bash
bash scripts/experiments/maniskill/run_stackcube_live_rgb_pipeline.sh --smoke --num-envs=10
```

本地 GPU full：

```bash
bash scripts/experiments/maniskill/run_stackcube_live_rgb_pipeline.sh --num-envs=100
```

full 成功后脚本自动执行 `trajectory-audit` 和 `freeze-data`。随后再用
`scripts/experiments/maniskill/convert_stackcube_dataset.sh` 将
`StackCube-v1/d_core/trajectory.h5` 转成 LeRobot 数据集。

## 不再使用的路线

`gpu_state_materializer`、`gpu_state_replay_*`、RGB materialization validation 和旧的
state-materialized D_core 均不属于正式 M1-W 数据线。今后新采视觉数据必须在实际 action
执行时直接保存 `obs_mode="rgb"`；本次 baseline 之所以无 RGB，只是因为它是失败筛选阶段，
repair 与 final 已按 live RGB 规则保存。

## 完成标准

- native source、baseline、repair、merge、final 的 fingerprint 集合闭合且无重复。
- baseline 失败集被完整处理；repair gate 通过。
- final `replay_manifest.json` 的 episode 数量完整、RGB schema 正确、env_states/action 对齐，
  且 `successful_at_end / episode_count = 1.0`。
- trajectory audit、D_core 和 LeRobot conversion 只引用 final live RGB replay。
- state banks 的 train/development/test 数量、fingerprint 唯一性和跨 split leakage gate 通过。
