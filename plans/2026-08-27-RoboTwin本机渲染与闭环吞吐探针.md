## 结论

**渲染速度可接受，可以继续做真实 checkpoint 的小规模 smoke。**

本机 RTX 3090、驱动 580.173.02、`click_bell` + `demo_clean`、seed 100000、
`render_freq=0`、四路相机（left/right/head/front）：

| 项 | median | max |
| --- | ---: | ---: |
| `setup_demo`（一次性场景构建） | 23.34 s | — |
| `get_obs()` | **106.2 ms** | 115.8 ms |
| `take_action()`（qpos，±0.02 rad 小扰动） | **47.4 ms** | 48.0 ms |
| `chunk24` = 1 次 `get_obs` + 24 次 `take_action` | **≈ 1.24 s** | — |

都在几十到一百毫秒量级、不是秒级，环境侧不会成为迭代瓶颈。`chunk24` 对应
FastWAM 的 `skip_get_obs_within_replan=true, replan_steps=24` 口径。

走的是**真实** `envs/click_bell.py` + 真实 `CuroboPlanner`，不是绕过 curobo 的
替代管路。

## 结果的三条限制

- **`take_action` 的 47.4 ms 可能偏慢**。全程有一条 warning：
  `Warp CUDA error: Failed to get driver entry point 'cuDeviceGetUuid' (CUDA error 1)`
  / `API call is not supported in the installed CUDA driver`。`warp-lang 1.5.1`
  与驱动 580 不完全兼容，curobo 的 GPU 加速可能退化到部分功能受限。这只影响
  走 planner 的 `take_action`，不影响纯 SAPIEN 渲染的 `get_obs`。目前无法区分
  47.4 ms 是退化值还是 warning 无实质影响。
- **这是 RTX 3090 的数字**，远端 H20 渲染性能不同，需要重测才能用于远端规划。
- 合成小扰动不是 WAM 的动作分布，`take_action` 耗时只是环境侧下界；正式评测
  还有 expert check、模型推理、成功判定后的额外取图等未计入。

## 环境安装记录（后续更新 Docker 可直接复用）

vendored RoboTwin 在
`third_party/w0_fastwam/FastWAM/third_party/RoboTwin`，revision
`bf44be51cf5717a5595ce59447f2cf5263d2aa95`。`task_config/`（含
`demo_clean.yml`、`demo_randomized.yml`、`_embodiment_config.yml`、
`_eval_step_limit.yml`、`_camera_config.yml`）与 `assets/`（30 GB，
embodiments/objects/background_texture 均已解压）**都已就位**，不需要再下载。

装到 `fastwam-upstream` 环境（Python 3.10、torch 2.7.1+cu128）：

```bash
# 1. CUDA 编译器与完整 toolkit（conda 内，无需 sudo；版本必须对齐 torch 的 cu128）
conda install -n fastwam-upstream -c nvidia "cuda-nvcc=12.8.93" -y
conda install -n fastwam-upstream -c nvidia "cuda-toolkit=12.8" -y

# 2. 新版 conda cuda 包用 targets/<arch>/include 布局，torch 的 cpp_extension 只找
#    $CUDA_HOME/include，需要软链，否则报 "cuda_runtime.h not found"
ENV=<path-to-conda>/envs/fastwam-upstream
for f in "$ENV"/targets/x86_64-linux/include/*; do
  [ -e "$ENV/include/$(basename "$f")" ] || ln -s "$f" "$ENV/include/$(basename "$f")"
done

# 3. curobo 必须用 v0.7.8。官方 _install.sh 里的 `git clone` 不指定 tag，现在
#    clone 默认分支会装到 2026-07 之后的重构版：那版把 curobo.wrap.* 整体移到
#    _src/ 并改了公共 API，RoboTwin 期待的 curobo.wrap.reacher.motion_gen 不存在。
cd third_party/w0_fastwam/FastWAM/third_party/RoboTwin/envs
git clone --depth 1 https://github.com/NVlabs/curobo.git
cd curobo && git fetch --depth 1 origin tag v0.7.8 && git checkout v0.7.8
CUDA_HOME=$ENV TORCH_CUDA_ARCH_LIST="8.6" \
  pip install -e . --no-build-isolation   # 编译 CUDA 扩展，约几分钟

# 4. warp-lang 必须降级：curobo v0.7.8 用 wp.torch，而 warp 1.16 已移除该模块
pip install "warp-lang==1.5.1"
```

验证：

```bash
cd third_party/w0_fastwam/FastWAM/third_party/RoboTwin
PYTHONNOUSERSITE=1 PYTHONPATH=. python -c "
from envs.robot.planner import CuroboPlanner; print('CuroboPlanner OK')"
```

`curobo` 装在 `envs/curobo`（v0.7.8，detached HEAD），不是 pip 包缓存，重建
Docker 时这一层要么一起 COPY，要么按上面步骤重装。

### 已知副作用

  pytorch3d，本次未装，仅影响用不到的可选功能。

## 复现探针

探针脚本是一次性的，未入库（放在 `/tmp/probe_v3.py`）。逻辑：按
`script/collect_data.py` 的方式从 `task_config/demo_clean.yml` +
`_embodiment_config.yml` 组装 kwargs（`setup_demo` 不会自己读盘，
`domain_randomization` 等字段必须由调用方传入），然后

- 3 次 `get_obs()` warm-up 不计时（SAPIEN 首次 shader 编译很慢）
- 10 次 `get_obs()` 计时
- 20 次 `take_action(qpos, action_type='qpos')` 计时，动作是当前 qpos 前 6 维
  交替 ±0.02 rad，不触碰夹爪
