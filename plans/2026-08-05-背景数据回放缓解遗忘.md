## 目标

已测得的三个事实把可行方向收窄到了数据侧：

| | 目标 canonical | 背景任务 |
|---|---:|---:|
| B0（记录） | 0/90 | 183/210 |
| C1（Non-PEFT，全量 action expert） | 87/90 = 96.7% | **0/210** |
| C2（LoRA rank 32，主干冻结） | 87/90 = 96.7% | **8/210 = 3.8%** |

C1 与 C2 的数据、LR、步数、batch、seed 完全相同，唯一差别是参数化方式，而遗忘程度几乎不变。
这说明根因不是"训练了多少参数"，而是**训练数据里没有背景任务，损失函数里不存在保留旧行为的
项**。本计划直接补上这一项，回答：需要多少背景数据才能保住多少旧能力，代价是多少目标能力。

## 执行步骤

### 1. 新增回放采样器

现有 `UniformTaskEpisodeSampler`（`target_training.py` 第 276 行）只在 3 个目标任务上做
「均匀任务 → 均匀 episode → 均匀帧」。新增一个双池采样器，**保留原采样器不变**（C1/C2/C3 的
正式训练仍用它）。

设计：

- 全局 batch 固定为 8，因此回放比例用 `ρ = k/8` 表示，`k` 为每个 batch 中来自背景池的样本数。
  `k` 取整数，比例是**逐 batch 精确的**，不用随机比例。
- 8 卡 × 每卡 batch 1 时，按 rank 分池最直接：rank `0 … 8-k-1` 抽目标池，rank `8-k … 7`
  抽背景池。这天然满足精确比例，且不需要跨卡通信。
- 两个池内部各自沿用「均匀任务 → 均匀 episode → 均匀帧」，背景池是 37 个任务、1,412 条
  episode；目标池是 3 个任务、113 条。
- 采样必须可复现：给定 seed 与 world size，两次构造产出完全相同的索引序列。参照现有采样器的
  确定性测试。
- `ρ` 的粒度与 `data_parallel_layout` 绑定：`8x1` 下为 1/8。若用 `4x2`，每卡 2 个样本，
  仍能表达 `k/8`，但 rank 分池要改成「rank 内分池」，实现时一并覆盖。

### 2. 训练入口接受回放比例

`c1_training.py` 增加 `--background-replay=k`（整数 0–7，默认 0）与
`--background-split-file=FILE`（默认 `configs/experiments/smolvla_libero/background_split.json`）。

- `k=0` 时行为与现在完全一致（用原采样器，不读背景 split）；
- `k>0` 时必须是 `--mode=diagnostic`，否则报错——本计划不产出正式 checkpoint；
- `run_config.json` 的 `dataset` 段记录 `background_replay_k`、`replay_fraction`、
  `background_split_sha256`、以及两个池的 episode 数与帧数；
- `sampler` 字段写 `dual_pool_rank_split_v1`，与原来的
  `uniform_task_then_uniform_episode` 区分开。

### 5. 预先注册的停止规则

**在看到 ρ=4/8 的结果之前定死**：以其 6 个 checkpoint 中背景成绩最高的那个为准，

- 若背景 **< 42/210**（即 B0 记录值 183/210 的 23%，等价于"平均每任务还救不回 6 条"），

## 判断标准

**执行前写死。看到数字之后不得修改。**

| 判据 | 阈值 | 不满足时怎么办 |
| --- | --- | --- |
| `k=0` 时行为不变 | 与改动前逐项一致（原采样器、不读背景 split、可跑 formal） | 修实现，不得影响 C1/C2/C3 的正式训练路径 |
| `k>0` 强制 diagnostic | `--background-replay>0` 且非 `--mode=diagnostic` 时报错 | 修实现，防止诊断产物混入正式对照 |
| 比例精确性 | 每个 batch 中背景样本数恒为 `k`，目标为 `8-k`，无随机波动 | 修实现 |
| 采样可复现 | 同 seed 同 world size 两次构造产出完全相同的索引序列 | 修实现 |
| 两池不重叠 | 采样器实际用到的 episode 索引与 `background_split` / `target_split` 的 train 集合分别一致，交集为空 | 停止 |
| checkpoint 完整性 | 每个变体保留 `005000`…`030000` 六个，评测期间不删 | 停止，曲线缺点即失去意义 |
| 背景评测规模 | 每次 210 条、7 任务 × 30 状态、`env_seed=1000` / `policy_seed=2000` / `n_action_steps=10` | 停止，缩减即不可与 183/210 比 |
| ρ=4/8 停止规则 | 背景最高分 ≥ 42/210 才继续补其余比例 | 按规则停止并记为负结果 |
| 溯源隔离 | 所有变体 `run_config.json` 为 `mode=diagnostic` 且带 `experiment_tag` 与 `background_replay_k`；选模产物 `selection_set` 为 `diagnostic_target_validation` | 修实现 |
| 一次性 | 每个比例训练一次、评测一次；看过曲线后不得追加比例或步数 | 需要更多点时另起计划并说明理由 |

**本计划不预设结论。** 四种结局都合法：

- 回放有效且目标能力几乎无损 → 找到了可用配置，但仍需另起正式计划重训重测才能进入对照；
- 回放有效但目标能力明显下降 → 存在权衡，需要在报告里给出曲线而非单点；
- 回放无效（ρ=4/8 也救不回来）→ 负结果，说明问题比"数据里缺旧任务"更深；
- 目标任务在 30000 步内不收敛 → 记为负结果，不要延长步数。

**本计划产出的 checkpoint 一律不得用于正式对照。** 已发表的 C1（目标 96.7% / 背景 0/210）
与 C2（96.7% / 8/210）不因本计划改变。

## 风险与停止条件

- **回放会让背景 test 从"遗忘检验"变成"同分布检验"。** ρ>0 的变体在训练中见过背景任务的
  demonstration，因此它的背景成绩与 B0 的 183/210 是同一性质（同任务、未使用过的摆放），
  而不再是"忘没忘"。这恰好让与 B0 的比较变得对等，但报告里必须写清这个性质变化，不能与
  C1/C2 的 0/210、8/210 混为一谈——后两者是真正的遗忘读数。
- **不要同时改多个变量。** 本计划固定 LR 1e-4、30000 步、全局 batch 8、seed 1000，只动
  回放比例。与 LR 诊断计划的结果要分开陈述。
- **按 rank 分池会让每张卡的数据分布倾斜。** SmolVLA 训练的部分不含 BatchNorm（LayerNorm 是
  逐样本的），因此梯度平均后等价于混合批；但若将来引入任何跨样本统计的层，这个实现就不再
  等价，需要改为 rank 内混合。实现时在注释里写明这个前提。
- **目标池会被反复重采。** ρ=4/8 时目标池每步只贡献 4 个样本，30000 步共 120,000 个目标样本，
  对 11,022 帧仍是 10.9 个 epoch；而背景池 120,000 个样本对 236,470 帧只有 0.51 个 epoch。
  两个池的 epoch 数天然不对称，这是设计的一部分，不是错误，但解读曲线时要记住。
- 单个变体的评测量是 360 条目标 + 6 × 210 条背景 = 1,620 条 300 步 rollout，加一次 30000 步
  训练。三个比例全跑约 4,860 条。务必 `--num-gpus=8` 并支持 `--resume`。
