### 1. 把正式协议的不变量从"卡数"改成"全局 batch"

- 保留 `FORMAL_GLOBAL_BATCH_SIZE = 8` 作为唯一冻结的批量不变量；

  改名为 `DEFAULT_WORLD_SIZE`/`DEFAULT_BATCH_SIZE` 并保留旧名作别名（C2/C3 从本模块导入这两个

  - 删掉第 263 行无条件的 `batch_size != FORMAL_BATCH_SIZE` 拒绝（它连 smoke 都不允许

### 2. 加入可见 GPU 数预检

同一文件的 fresh 校验里补一条：`num_processes` 超过 `torch.cuda.device_count()` 时立即失败，
错误信息给出请求值、可见值，并提示用 `CUDA_VISIBLE_DEVICES` 选卡。当前 launcher 固定
`--gpu_ids=all`（`scripts/experiments/smolvla_libero/train_c1.sh` 第 142 行），`all` 指"全部可见
GPU"，因此选特定卡用 `CUDA_VISIBLE_DEVICES` 即可，不新增参数。

### 3. run_config 记录数据并行布局

`build_run_config` 的 `training` 段已有 `world_size` / `per_gpu_batch_size` /
`global_batch_size`，再补一个 `data_parallel_layout`（形如 `"4x2"`）便于报告直接引用。
不同 `num_processes` 的 run 与 8 卡 run **协议等价但不是逐位复现**：sampler 的分片与数据
读取顺序随 world size 变化。这一句必须同时写进 guide。

## 判断标准

**执行前写死。**

| 判据 | 阈值 | 不满足时怎么办 |
| --- | --- | --- |
| 步骤 5 后 preflight | `resolve_c1_base_policy(..., require_selection=True)` 返回成功 | 停止，检查 selection provenance 而不是改用其他 checkpoint |
| 发布出的 `selected/pretrained_model/model.safetensors` | sha256 与 `checkpoints/025000` 同名文件一致 | 停止并删除发布目录 |
| `selected_checkpoint.json` | `step=25000`、`status=complete`、`selection_set=background_validation` | 停止 |
| formal + `4×2`、`2×4`、`1×8`、`8×1` | 全部通过校验，`--num_processes` 与请求值一致 | 修实现 |
| formal + 全局 batch ≠ 8（如 `4×1`、`8×2`） | 全部被拒绝 | 修实现，不得放宽 |
| `num_processes` > 可见 GPU 数 | 立即失败且信息可读 | 修实现 |
| resume 改卡数 | 仍然失败 | 修实现 |
| C1/C2/C3/B0 相关单测 | 全绿 | 修完再往下 |
| 步骤 9 smoke | `checkpoints/000002/` 含 `pretrained_model/` 与 `training_state/`，两步 loss 有限 | 若 batch 1 BF16 仍 OOM，按 guide 写 `N_A.json` 记 `reason="oom"`，不缩小模型 |

正式 C1 结果只有在 `steps=30000`、`save_freq=5000`、`lr=1e-4`、`seed=1000`、`bf16`、
全局 batch 8 全部满足时才可标记为 `Formal`；`data_parallel_layout` 必须一并记录。

## 风险与停止条件

- **不要用 `--base-policy` 指向 `checkpoints/last` 或某个 step 来绕过 provenance。**
  fail closed 是设计意图；绕过就等于用未经选模的权重当 C1 起点，后面所有 C1/C2/C3
  比较全部作废。
- **不同卡数不是逐位复现。** 相同全局 batch 下协议等价，但 sampler 分片与数据顺序随
  world size 改变，因此 4 卡 run 与 8 卡 run 的 loss 曲线不会重合。报告里必须写出
  `data_parallel_layout`，不能把两者当同一次运行的重复。
- 少于 8 卡时 per-GPU batch 会上升（1 卡需 batch 8），显存风险随之上升。OOM 时按 guide
  的 `N_A.json` 契约记录，不缩小模型、不降全局 batch。
- 步骤 5 会往正式产物目录写入 `checkpoints/selected`。执行前确认 `--selection-file`
  来源可信；目标已存在时不要盲加 `--overwrite`。
- 不要在本计划里顺手启动 30,000 步正式训练。本计划只负责让它能启动，正式运行与结果登记
  另起计划。
