## 目标

已测得的事实：C1（selected 030000）目标任务 canonical 87/90 = 96.7%，同一份背景 test
**0/210**，210 条全部 `time_limit`，对照 B0 记录的 183/210。这是彻底的灾难性遗忘。

诊断中发现两处配置不对称，都指向「优化走得太远」：

| | B0 | C1 |
|---|---:|---:|
| learning rate | 1e-4 | 1e-4（同一个常量） |
| global batch | 64 | **8** |
| 训练帧数 | 236,470 | 11,022 |
| epoch 数 | 8.12 | **21.77** |

`FORMAL_LEARNING_RATE = 1e-4` 定义在 `b0_training.py` 第 49 行并被 C1 直接导入，但两者的
global batch 差 8 倍，LR 没有随之缩放。同时目标任务在 **step 15000 就饱和**
（0.9833，与 30000 同值），而训练 loss 一路降到 30000（0.0926 → 0.0185）——后 15000 步对
目标任务毫无贡献。

本计划要量出：背景能力是**立即**丢失还是**逐步**流失；早停与降 LR 各能挽回多少；代价是多少
目标任务成绩。

## 执行步骤

### 1. 加入 diagnostic 训练模式

`c1_training.py` 的 LR 与 seed 校验在 `mode != "formal"` 之前（约第 273–277 行），因此**连 smoke
都不允许改 LR**。变体 B 需要一个明确的、不会与正式结果混淆的出口。

改法：`--mode` 增加 `diagnostic` 取值。

- `diagnostic` 模式必须同时给出 `--experiment-tag=<短标签>`，否则报错；
- 该模式允许覆盖 `--learning-rate` 与 `--steps`，其余冻结项（seed 1000、BF16、全局 batch 8、
  `save_freq`）仍然强制；
- `run_config.json` 的 `training.mode` 写 `diagnostic`，并新增 `training.experiment_tag`；
- **fail closed**：`target_checkpoint_selection.py` 与 `b0_test_evaluation.py` 读到
  `mode=diagnostic` 的 run 时，产物里必须标记 `result_set` 带 `diagnostic` 前缀，且
  `selected_checkpoint.json` 的 `selection_set` 写 `diagnostic_target_validation`，
  使它无法被目标协议评测当作正式 winner 使用；
- `formal` 与 `smoke` 两种模式的行为一字不变。

### 2. 变体 A：同配置复跑，保留全部 checkpoint

目的是拿到「原配置下背景能力随步数如何流失」的曲线。配置与已发表的正式 C1 完全一致
（LR 1e-4、30000 步、全局 batch 8、`8x1` 布局、seed 1000），唯一差别是产物不删。

```bash
bash scripts/experiments/smolvla_libero/train_c1.sh \
  --mode=diagnostic \
  --experiment-tag=a_same_config \
  --num-processes=8 --batch-size=1 \
  --steps=30000 --save-freq=5000 \
  --learning-rate=0.0001 \
  --output-dir=outputs/smolvla_libero/diagnostic/c1_a_same_config
```

**六个 checkpoint 一个都不能删**，它们是本计划的核心产物。

### 3. 变体 B：学习率按 batch 线性缩放

B0 是 `lr=1e-4 @ gb=64`；C1 的 gb=8，线性缩放得 `1e-4 × 8/64 = 1.25e-5`。

```bash
bash scripts/experiments/smolvla_libero/train_c1.sh \
  --mode=diagnostic \
  --experiment-tag=b_scaled_lr \
  --num-processes=8 --batch-size=1 \
  --steps=30000 --save-freq=5000 \
  --learning-rate=0.0000125 \
  --output-dir=outputs/smolvla_libero/diagnostic/c1_b_scaled_lr
```

选择线性缩放而非 sqrt 缩放（后者为 `1e-4/√8 = 3.54e-5`）：线性是更常见的约定，且与 B0 的
`gb=64` 形成更清晰的对比。这个选择在执行前定死，不因结果调整。

LR 降低后目标任务饱和会更晚，30000 步内可能不饱和——**若不饱和，这本身就是结论**，不要延长
步数（延长会引入新的自由度，与变体 A 不可比）。

### 4. 两个变体的目标任务曲线

对每个变体跑一次共用选模，得到 6 个 checkpoint 的目标 macro SR（各 60 条闭环）：

```bash
for tag in c1_a_same_config c1_b_scaled_lr; do
  bash scripts/experiments/smolvla_libero/select_checkpoint.sh \
    --run-dir=outputs/smolvla_libero/diagnostic/${tag} \
    --dataset-root=datasets/lerobot/lerobot/libero \
    --suite=libero_goal --task-ids=1,4,8 \
    --split-file=configs/experiments/smolvla_libero/target_split.json \
    --checkpoint-steps=5000,10000,15000,20000,25000,30000 \
    --policy-seed=1500 --num-gpus=8 \
    --output-dir=outputs/smolvla_libero/diagnostic/${tag}/checkpoint_selection \
    --selected-dir=outputs/smolvla_libero/diagnostic/${tag}/checkpoints/selected
done
```

这里只取排名表里的逐 checkpoint 成绩，**不使用它选出的 winner**——本计划不产出可用于后续
评测的 checkpoint。

### 5. 两个变体的背景任务曲线

对每个变体的 6 个 checkpoint 各跑一次完整背景 test（7 任务 × 30 状态 = 210 条）：

```bash
for tag in c1_a_same_config c1_b_scaled_lr; do
  for step in 005000 010000 015000 020000 025000 030000; do
    bash scripts/experiments/smolvla_libero/eval_b0_test.sh \
      --run-dir=outputs/smolvla_libero/pilot/b0_domain_adaptation_offline \
      --policy-path=outputs/smolvla_libero/diagnostic/${tag}/checkpoints/${step}/pretrained_model \
      --model-label=${tag}_${step} \
      --num-gpus=8 \
      --libero-assets-dir=datasets/raw/libero_assets \
      --output-dir=outputs/smolvla_libero/diagnostic/${tag}/background/${step}
    done
done
```

不缩减 init states——只有完整 210 条才能与 B0 记录的 183/210 直接比。
合计 `2 × 6 × 210 = 2,520` 条背景 rollout，加上步骤 4 的 `2 × 360 = 720` 条目标 rollout。

## 判断标准

**执行前写死。看到数字之后不得修改。**

| 判据 | 阈值 | 不满足时怎么办 |
| --- | --- | --- |
| 变体 A 与正式 C1 的一致性 | 变体 A 的 step 30000 目标 macro SR 与正式 C1 选模记录的 0.9833 一致（±1/60，即允许差 1 条） | 差异更大则说明训练不可复现，停止并查环境或代码漂移 |
| 变体 A 的背景终点 | step 30000 背景成绩与已测的 0/210 一致（允许 0–2 条） | 同上 |
| diagnostic 隔离性 | 两个变体的 `run_config.json` 为 `mode=diagnostic` 且带 `experiment_tag`；选模产物的 `selection_set` 为 `diagnostic_target_validation`；无法被目标协议评测当作正式 winner | 修实现，隔离失效会污染已发表结论 |
| formal/smoke 行为不变 | 不给 `--mode=diagnostic` 时与改动前逐项一致（LR/seed 仍冻结） | 修实现 |
| checkpoint 完整性 | 两个变体各保留 `005000`…`030000` 六个，评测期间不得删除 | 停止，曲线缺点即失去意义 |
| 背景评测规模 | 每次 210 条，7 任务 × 30 状态，`env_seed=1000` / `policy_seed=2000` / `n_action_steps=10` | 停止，缩减即不可与 183/210 比 |
| 曲线可读性 | 每个变体都能给出 6 个 (目标, 背景) 数据点 | 补齐缺失点 |
| 一次性 | 两个变体各训练一次、各评测一次；看过曲线后不得追加 LR 取值或步数 | 需要更多点时另起计划并说明理由 |

**本计划不预设结论。** 四种结局都合法，照实记录：

- 背景能力在 step 5000 就已归零 → 早停与降 LR 都买不到东西，必须走数据回放或 LoRA；
- 背景能力逐步流失 → 存在真实权衡曲线，早停是便宜有效的杠杆；
- 变体 B 保留明显更多而目标成绩相当 → LR 未随 batch 缩放是主要加重因素；
- 变体 B 目标任务在 30000 步内不饱和 → 降 LR 的代价过高，记为负结果。

**本计划产出的 checkpoint 一律不得用于后续正式评测。** 已发表的正式 C1 结果
（目标 96.7% / 背景 0/210）不因本计划改变。

## 不在本计划范围

- **背景数据回放**（把 B0 的背景 demonstration 混进 C1 训练）。这是唯一能在损失函数里真正
  约束漂移的做法，也最贵：要新增采样比例这个超参，背景侧有 236,470 帧。见 C1 guide 的 TODO。
- **改用 LoRA**（即 C2/C3）。低秩增量、主干不动，先验上遗忘更轻；C2/C3 训练完必须跑同一份
  背景 test 才能验证。见 C1 guide 的 TODO。
- 其他缓解手段（EWC、参数正则、更严冻结边界、更小 rank）。
- 重跑 B0 的背景 test。基线仍取文档记录的 183/210。

## 风险与停止条件

- **不得让诊断产物污染已发表结论。** 已发表的 C1 是 LR 1e-4 / 30000 步 / 目标 96.7% /
  背景 0/210。本计划的任何 checkpoint 都不得进入目标协议评测，也不得替换
  `pilot/c1_default_non_peft/checkpoints/selected`。`mode=diagnostic` 的 fail-closed 标记
  就是为此设置的。
- **变体 A 必须先复现出已知终点。** 若它的 step 30000 拿不到目标 0.9833 与背景 0/210，
  说明训练链路已漂移，此时曲线没有解释力，停止。
- **基线来自文档记录。** B0 的 183/210 取自 `reports/experiment_log.md` 与
  `reports/guides/smolvla_libero/02_b0_domain_adaptation.md`，原始产物已丢失、本计划不重跑。
  报告里必须写明这一点。
- **早停不是免费的。** 即便 step 15000 背景保留更好，它的目标成绩 0.9833 是在 60 个
  validation 状态上测的，与 test 上的表现不是同一个数。若要把早停点当作新的正式配置，需要
  另起计划、重新走完整的选模与 test 流程。
- **降 LR 会改变饱和点。** 变体 B 的 6 个 checkpoint 可能整体偏左（尚未学会），此时与变体 A
  按 step 对齐比较是不公平的——应按「目标成绩相当」的点对齐比较背景保留，这一点在步骤 6
  的汇总里写清楚。
- 合计 3,240 条 300 步 rollout 加两次 30000 步训练，务必 `--num-gpus=8` 并支持 `--resume`。
