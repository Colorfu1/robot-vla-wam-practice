## 已冻结决议

### 数据源、controller 与 formal horizon

| 任务 | 唯一数据源 | 源 controller | M1 目标 controller | action 维度 | 原生 horizon | formal IL horizon |
| --- | --- | --- | --- | ---: | ---: | ---: |
| `StackCube-v1` | 官方 `motionplanning/trajectory.h5` | `pd_joint_pos` | `pd_ee_delta_pos` | 4 | 50 | **200** |
| `PegInsertionSide-v1` | 官方 `motionplanning/trajectory.h5` | `pd_joint_pos` | `pd_ee_delta_pose` | 7 | 100 | **300** |
| `PlugCharger-v1` | 官方 `motionplanning/trajectory.h5` | `pd_joint_pos` | `pd_ee_delta_pose` | 7 | 200 | **审计后按下式冻结** |

- 三个任务统一保留 motion-planning 数据；不因原生 horizon 不兼容而切 RL 数据。
- `StackCube-v1` 和 `PegInsertionSide-v1` 对齐 ManiSkill 官方 tuned IL baseline 的
  `max_episode_steps=200/300`。
- 三个原生 horizon `50/100/200` 只输出 `success_by_native_horizon` 诊断，不 gate M1，
  不作为主训练或 formal evaluation 协议。
- M1 的 canonical replay 和 formal evaluation backend 为 `physx_cpu`，与 motion-planning 源一致。
  后续 R0 若需转 `physx_cuda` 做在线 RL，必须在 M2-R/R0 子计划里另做跨 backend
  replay/success 对照，不将 GPU 数字混入本 M1 的 CPU formal 协议。

### PlugCharger horizon 的确定规则

Plug 在全量 target-controller replay 结束前，`formal_horizon` 必须保持未冻结，不先写
`250` 或任意人工数字。全量审计后使用成功 replay 轨迹在 trim 前的低层 action
长度 `T_i` 计算：

```text
mean_demo_length = arithmetic_mean(T_i)
raw_horizon = 2 * mean_demo_length
rounded_horizon = 100 * floor(raw_horizon / 100 + 0.5)
formal_horizon = max(200, rounded_horizon)
```

这是“约 `2× mean demonstration length`，四舍五入到最近 100 步”的确定性实现。必须先
落盘 first-success、post-success-tail 和 mean-length 审计，再由程序生成 horizon decision。
如果计算后 `success_by_formal_horizon < 99%`，Plug 协议记为 `blocked`，不在看到数字后
手工增大 horizon。

### observation 与时序边界

M1 冻结两套用途不同的 schema：

1. `visual_student_v1`（Stack/WAM 主候选，Plug 可视候选）：
   `observation.images.base_camera` + `observation.images.hand_camera`，两路 `uint8 128×128 RGB`；
   `observation.state = qpos(9) + qvel(9)`，共 18D。不给 object pose、goal pose、success flag
   或手工 relative vector。
2. `peg_state_base_v1`（Residual R0）：`qpos(9) + qvel(9) + tcp_pose(7) + peg_pose(7)
   + peg_half_size(3) + box_hole_pose(7) + box_hole_radius(1)`，共 43D。这是有意使用的
   low-dimensional state base，不当作视觉 student 结果。

两者都使用 `control_freq=20 Hz`。Peg R0 时序接口按母计划冻结为
`observation horizon=2 / prediction horizon=16 / action horizon=4 / execution steps=4`。M1 只对
Stack/Plug 的 `2/16/4` 与 `2/16/8` chunk slicing 做不跨 episode、mask/padding 正确性验证；
Mini-WAM 最终 execution steps 由 M2-W 冻结，不在 M1 用数据审计伪装成性能选型。

### `D_core` 清理与 split

- 每条 replay 轨迹只保留到 `min(T, first_success + 5)`；不填充额外五帧。
- 没有达到冻结 success predicate 的 replay 不进 `D_core`，但仍保留在审计产物中。
- 对清理后 episode 先按 first-success decile 分层，层内按
  `SHA256(task + source_episode_id)` 排序；固定分出 100 条 offline test、100 条 offline
  development，其余为 offline train。test 在 M2 配置冻结前不读。
- 另生成 task-specific CPU initial-state banks：`train=2000`、`development=200`、
  `test=400`；起始 seed 分别为 `10000/20000/30000`，每个 seed 单环境 reset，
  `reconfiguration_freq=1`，并保存实际 state，不把 seed 整数当作 state 本身。
- demonstration train/development/test 与三个 initial-state bank 都做任务专属指纹对照；
  四元数按 `q` 与 `-q` 等价正则化，数值容差 `1e-4`。

### 5A. Peg controller conversion diagnosis（仅在 Peg smoke 失败时）

如果 Peg 的 10 条 smoke 失败，先执行两个彼此独立的最小 probe；不放宽原有 10/10
gate，不改 task、success predicate、horizon 或 backend。两个 probe 都从相同的官方
`pd_joint_pos` source H5 出发，并各自保存 H5、JSON、逐 episode 诊断和汇总，失败后可从
已完成 worker 继续。

```bash
bash scripts/experiments/maniskill/run_peg_conversion_probe.sh \
  --mode=fixed_delta --count=10 --num-workers=10 \
  --output-dir=outputs/maniskill/m1_protocol_audit/PegInsertionSide-v1/conversion_probe/fixed_delta

bash scripts/experiments/maniskill/run_peg_conversion_probe.sh \
  --mode=absolute --count=10 --num-workers=10 \
  --output-dir=outputs/maniskill/m1_protocol_audit/PegInsertionSide-v1/conversion_probe/absolute
```

`fixed_delta` 的完整 contract 是：源 action 先推进 source controller，读取 source
controller 的 target qpos，Pinocchio FK 得到目标 EEF；随后按
`q_target * inverse(q_current)` 求相对旋转，并显式使用 Panda 当前
`physical_rotvec = -normalized_action * abs(rot_lower)` 的符号。每个 source action 最多
执行 16 个 target steps，每一步都重新计算 EEF error，直到位置误差 `<=2 mm` 且旋转误差
`<=0.01 rad`。`absolute` 不做 delta accumulation：每个 source target qpos 直接 FK 到
`pd_ee_pose` 的 base-frame absolute target，每个 source action 只执行一次。

两个 probe 的 gate 都是 target episode 的 `success_at_end == 10/10`；其输出的
`rotation_clip_count`、`inner_steps_by_source_step`、最终 EEF error 和 target/source
length ratio 用来解释转换是否可靠，而不是替代 M1 formal replay。若 B/C 任一通过，才把
该 conversion contract 集成回 M1 runner 并重新执行原始 Peg smoke；若两者仍稳定失败，
再进入“直接生成 EEF demonstrations”的单独决策，不在本计划中偷偷换数据源。

## 判断标准

**以下阈值在全量 replay 之前冻结，看到结果后不改。**

| 判据 | 阈值 | 不满足时怎么办 |
| --- | --- | --- |
| archive 身份 | revision 和三个 zip SHA-256 与前置条件完全一致 | 停止；不用 `main` 新文件替代 |
| source 结构 | 每任务恰好 1000 条，metadata success 1000/1000，H5/JSON ID 100% 对齐 | 停止并检查 archive/解压/版本 |
| source contract | 只允许 motion-planning + `pd_joint_pos` + `obs_mode=none` | 停止；禁止切 RL demonstrations |
| replay smoke | 每任务 10/10 成功，无 crash/non-finite | 停止，不跑全量 |
| 全量 replay survival | 每任务 `successful target replay / 1000 >= 95%` | 停止；修 controller conversion/状态恢复，不换数据源 |
| `D_core` 数量 | 每任务最终可用 episode `>=900` | 该任务 M1 `blocked`，不进 M2 |
| target action contract | Stack `4D pd_ee_delta_pos`；Peg/Plug `7D pd_ee_delta_pose`；non-finite=0，`max_abs <= 1+1e-5` | 停止；不静默 clip 清洗数据 |
| 训练数据 clipping | 转换/冻结阶段 clip count=0；只记录 channel statistics | 停止并定位 converter/action scale |
| formal-horizon coverage | Stack@200 `>=99%`；Peg@300 `>=99%`；Plug@公式结果 `>=99%` | 该任务 `blocked`；不手工加 horizon |
| native-horizon coverage | 只报 Stack@50/Peg@100/Plug@200，无通过阈值 | 不影响 M1 gate，禁止换 RL 数据 |
| post-success trim | 进入 `D_core` 的每条轨迹最多保留 5 个 post-success action，合规率 100% | 停止并修 trim/index 实现 |
| chunk slicing | 有效 action 不跨 episode；padding mask 100% 与人工 toy episode 一致 | 停止，不进 LeRobot 转换 |
| visual schema | 两路 RGB 皆 `128×128×3 uint8`，proprio 恰好 18D，无 privileged pose/success | 停止并修 schema |
| Peg state schema | 恰好 43D，字段顺序和 manifest 一致 | 停止并修 flatten contract |
| sparse reward 一致性 | 逐帧 `sparse_reward == frozen_success` 一致率 100% | 停止；不让 data/RL/eval 用不同 label |
| Peg 几何 probe | 全部预期边界 label 100% 正确，strict-only false negative=0 | 停止并修 predicate/坐标系 |
| Peg 可达 false positive | 若计数>0，frozen env 必须是 `RobotPracticePegInsertionSideStrict-v1`；若=0，必须是 native ID | env 选择与证据不一致则停止 |
| split 数量 | offline dev/test 各 100；state bank train/dev/test 各 2000/200/400 | 停止并修 split generator |
| split 泄漏 | task-specific fingerprint 在任意跨 split 组合中 `1e-4` 内重复数=0 | 停止；换 state bank seed 需更新计划 |
| formal evaluation semantics | `physx_cpu`、20 Hz、无 partial reset、`ignore_terminations=True`，同时报 `success_once/success_at_end` | 停止，不将其他 backend/wrapper 结果并表 |

通过 M1 只说明“数据与协议干净到值得训练任务专属 base”，不说明任务难度、base
成功率、WAM 收益或 residual headroom。

## 风险与停止条件

- **官方 dataset `main` 可变。** 本计划固定 revision 和 zip SHA；不得因 downloader
  默认行为换成新 archive。
- **旧 metadata 与 3.0.1 API 可能不完全兼容。** replay 可显式 override
  `reward_mode=sparse`、target controller 和 backend，但不改 source H5/JSON；需更多 override 时先停。
- **motion-planning 轨迹跨过原生 TimeLimit。** 这是 IL-specific extended horizon 的预期背景；
  禁止使用 `--discard-timeout`、原生 horizon 过滤或 RL demonstrations 将问题隐去。
- **smoke 与 full 默认会产生同名 replay 文件。** runner 必须隔离输入/输出目录；
  路径冲突或试图覆盖已有 H5 时立即停止。
- **controller conversion 只在 CPU 有完整支持。** M1 不把这一步静默转到 GPU；
  后续 GPU online RL 属于独立 backend migration 问题。
- **Plug 在官方 IL replay 示例中没有现成条目。** 其 7D conversion 必须先过 10/10
  smoke；失败时修 conversion 或记为 blocked，不切数据源。
- **Peg 的 geometry 会 reconfigure。** 任何把单一 peg length、固定 `0.075` 或不同环境的
  box depth 混用的实现都立即停止。
- **Plug 不允许人工 horizon override。** 公式 gate 不通过就建 Plug 专项子计划，
  不在本计划里边看结果边加长。
- **M1 不是 baseline 训练。** 不记 train loss/open-loop policy error/closed-loop policy success
  为已测；实验日志中这些字段必须明确写 `N/A (protocol audit)`。
- 禁止将 archive、H5、state bank、逐帧 JSONL、视频或其他生成产物加入 git。
