### 4. 校验两次运行的协议一致性

比对两份 `run_manifest.json`，确认除 `policy_path` / `model_label` / `output_dir` 外逐项相同：
`target_split_sha256`、`paraphrases_sha256`、`env_seed`、`policy_seed`、`n_action_steps`、

任一项不同，两个成绩就不可比，必须查清原因后重跑，不得"事后说明差异"。

## 判断标准

**执行前写死。**

| 判据 | 阈值 | 不满足时怎么办 |
| --- | --- | --- |
| 工作量 | 两次运行各 21 job / 210 rollout，`status=complete` | 修/重跑，不接受部分完成的成绩 |
| 协议一致性 | 步骤 4 列出的字段两次逐项相同 | 停止，查清后重跑；不得事后解释差异 |
| 使用的 init states | 两次都恰好是三个任务各 30 个 test 状态，与 validation 零重叠 | 停止，选模集混入即作废 |
| C1 权重溯源 | `--policy-path` 指向的目录旁 `selected_checkpoint.json` 为 step 30000 / `target_validation` / `complete` | 停止，不得用 `checkpoints/last` 或任意 step 顶替 |
| Z0 权重溯源 | 与 B0 选模产出的 `025000` 权重 sha256 一致 | 停止 |
| 顺序纪律 | Z0 先于 C1 完成 | 若已先看 C1，如实记录顺序，不得据此调整 Z0 的任何参数 |
| 一次性 | 两次评测各只跑一次；看过结果后不得加 seed、改 horizon、换 checkpoint 或改协议 | 违反即整份结果作废 |

**本计划不预设"C1 一定优于 Z0"。** 若 C1 未显著优于 Z0，那就是负结果，照实记录；不得回头
改选模判据、换 checkpoint 或增减 validation 规模。

## 风险与停止条件

- **Z0 与 C1 是同一份权重家族的两端，唯一变量必须只有目标任务训练。** Z0 用 selected B0，
  C1 用从同一个 B0 出发训练出的 030000。若两次评测的协议字段有任何差异，测出来的差异里
  就混着协议差异，结论不成立。
- **C1 的 selected 路径本机缺失是已知障碍。** 与之前 C1 训练被 B0 selected 缺失挡住是同一类
  问题（产物目录多套了一层）。执行前必须确认，不要在评测中途才发现。
- **Prompt Swap 对 Z0 可能给出退化结果。** B0 从未在这三个任务上训练，它可能对任何指令都
  给出相似行为，导致混淆矩阵接近均匀。这本身是有信息量的（说明零样本下指令不起作用），
  但不要把它解读为"Prompt Swap 协议失效"。
- **不要因为 Z0 成绩太低就缩减它的规模。** 3 条可视化 rollout 全失败不代表正式跑也全失败；
  即使全失败，210 条的 0% 与 3 条的 0% 在证据强度上完全不同。
- 210 条 × 300 步的评测量不小，务必用 `--num-gpus=8` 并在中断后用 `--resume`，不要从头重跑。
